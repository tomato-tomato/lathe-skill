# Lathe —— 无 CLI 的动手实践教程 Skill

> 把 [Lathe](https://github.com/devenjarvis/lathe) 提炼成**不依赖 CLI 的 Agent Skill**（持续迭代中），让支持 Agent Skills 的编码助手按需生成、续写、复习、验证动手实践型技术教程。我自己用它学 Rust。

**当前版本 v0.6.0** ｜ 技能包下载：[Releases](https://github.com/tomato-tomato/lathe-skill/releases) ｜ 完整用法：[Lathe 技能使用教程](./docs/skills-tutorial.md)

这套 skill 要解决的不是「AI 能不能写出一篇教程」，而是三个更实际的问题：**承诺要讲的知识点有没有真的讲、讲在哪、没讲的去了哪**；**每次调用要读多少规则**（全技能约 300 KB，按操作拆分加载，列表/提问/扫描不会去读写作核心）；以及**改了规则之后旧教程要不要返工**（不需要，新字段缺失即视为空或自动回落）。

## 30 秒上手

```bash
# 1. 从 Releases 下载最新技能包并解压（如 lathe-0.6.0.zip，顶层只有 lathe/）
unzip lathe-0.6.0.zip -d ./skills-download

# 2. 连同 references/ 与 scripts/ 一起复制到技能目录（用户级：所有项目可用）
cp -r skills-download/lathe ~/.qoderwork/skills/
#    项目级：mkdir -p .qoderwork/skills && cp -r skills-download/lathe .qoderwork/skills/

# 3. 在客户端里输入 /lathe —— 技能加载成功会列出十一项操作让你选
```

然后直接给主题即可：`/lathe 用 Go 构建一个 Raft 共识算法实现`。技能会引导你确认保存位置与经验水平、锁定工具版本、研究主题、生成第一部分。

已在 **QoderWork** 与 **QoderWork CN** 上实测；技能采用标准 Agent Skills 布局（`SKILL.md` + `references/` + `scripts/`），也已确认兼容 Reasonix 等支持该标准的终端 Agent（复制到 `~/.reasonix/skills/` 即可）。其他客户端需要自行验证。

## Skills 功能一览

所有操作通过 `/lathe` 调用，中英文关键词均可（也支持不带 `/lathe` 的自然语言触发）：

| 操作     | 命令                                    | 功能                                                                                                                            |
| -------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 生成教程 | `/lathe <主题>`                         | 生成动手实践型教程的第一部分（动笔前先给大纲计划请你确认）                                                                      |
| 续写教程 | `/lathe 续写\|extend <slug> [指导]`     | 添加下一部分，可基于本地实际代码进度；新部分含目标达成回顾（该教程已有面试文档时自动同步本部分）                                |
| 收尾完结 | `/lathe 续写 收尾 <slug>`               | 生成总结部分（全课程回顾、知识图谱、练习方向）并完结课程；**账本还有欠债会先拦住**；续写可重新开放                              |
| 复习教程 | `/lathe 复习\|review <slug>`            | 生成复习材料：逐部分回顾、自测题、重跑检查点、可继续深入的方向，并单列「还没讲到的（按 ID）」（含 `面试` 关键词时转面试文档）   |
| 面试文档 | `/lathe 面试\|interview <slug> [part]`  | 生成按 Part 分章的面试要点文档（一句话回答 → 展开 → 追问点 → 我的项目里）；只对教学部分产出，中途启用会先检测遗漏再确认补写范围 |
| 验证教程 | `/lathe 验证\|verify <slug>`            | 临时/持久工作区中端到端执行教程，含版本冲突检测与修复；只执行可运行代码块与检查点                                               |
| 提问内容 | `/lathe 提问\|ask <slug> [part] <问题>` | 基于教程具体内容回答；发现教程错误时给出勘误确认块，**需要你手动确认**（回复「好」「嗯」不算）才会修改正文与同步复习材料        |
| 管理标签 | `/lathe 标签\|tag <slug>`               | 管理教程的搜索标签                                                                                                              |
| 创建语气 | `/lathe 语气\|voice [名称]`             | 创建自定义写作语气预设                                                                                                          |
| 扫描登记 | `/lathe 扫描\|scan [目录...]`           | 发现并登记散落各处的已有教程；参数也可以直接给教程目录（沙箱场景不必登记进用户配置）                                            |
| 列出教程 | `/lathe 列表\|list [slug]`              | 按语言分组列出教程及各部分状态，显示知识点积压条数与账本统计，结尾显示当前技能版本                                              |

## v0.6.0 做了什么

一句话主题：**你列出的知识点，一条都不能悄悄消失**。

- **知识点账本 `syllabus.json`**：每个承诺的知识点一行一条、六种状态（`planned` / `queued` / `taught` / `self-study` / `dropped_by_user` / `duplicate`）只改不删；`metadata.syllabus_ids` 做 ID 镜像（整条被删时能点名缺哪条），`knowledge_backlog` 是 `queued` 的投影。
- **写前计划确认 + 覆盖回执**：列了知识点、或有顺延/去重/闸门时先给计划请你确认；交付时附「知识点 → 章节」回执与对账等式，数字直接粘贴检查脚本的输出。
- **练习承接三档 + 积压治理**：每道题按档 1 融入 / 档 2 承接章 / 档 3 顺延分流；积压上限 14 条，触闸门默认扩 Part 而不是降级；档 1 承诺带 `promised_by`，上一部分答应「以后会讲」却没讲时，`ledger_check.py` 直接报 `已承诺未兑现`。
- **交付前试跑 + 技能自带检查脚本**：`scripts/` 下 `part_lint.py`（含复习材料专用档位）、`trial_run.py`、`ledger_check.py`（`--receipt` / `--finish` / `--continuity` / `--legacy`），纯标准库 Python 3，只检查本次新写的部分。
- **篇幅不是上限**：正文约 10,000 中文字符、单个 `runnable` 约 100–120 行只是观察值；拆不拆部分只看「独立里程碑 / 独立改动面 / 一次能否走完」，不得为控篇幅压缩解释或砍知识点。
- **读取端三轮实测的修复**：索引预算改成可达的（先定各字段条数上限，总量 2200 软 / 3000 硬）、复习改两段式按需读取（3 个部分实测总读取 243,718 → 约 92 KB，省 62%）、`metadata.json` 新增逐部分版本指纹 `part_versions`、收尾门禁在读取正文之前判定、旧历史的 0.6.0 前部分由脚本自动降级检查。

写侧与读取端各跑了多轮**真实执行**（外部 agent 独立跑生成 + 续写、隔离 agent 跑复习、主线程跑列表/门禁/提问），本版后半段的改动几乎都来自「让另一个执行者跑一遍」。完整变更清单见 [Releases](https://github.com/tomato-tomato/lathe-skill/releases)。

## 一些经历、牢骚😂

### 手边缺一个「在国内也能跑起来」的教程生成工具

身处 AI 爆发式增长的大环境，就一直都在找怎样把 AI 从「回答问题的聊天机器人」变成「能持续交付一套东西的生产工具」。受限于 Anthropic 对国内用户的各种限制，以及用国外优秀大模型要面对的各种问题，所以把关注点聚焦在**国内能用、好用、且最好不用花太多钱**的 AI 工具上。

国内确实见过一些专门针对「学习」这个方向的探索性产品，比如清华开源的 [openMAIC](https://open.maic.chat/)，还有千问小课堂（当前只在手机端找到入口，网页端和桌面端都找不到😂）。但它们的感觉都更适合学生群体：课堂模式，专注于讲透某个知识点。Google 实验室那个 Learn your way 我盯了很久，想上传一整套官方教程文档让它生成课程，结果它一直让我填一个表格，始终无法进入使用😩。后来偶然发现网页版 Gemini 的学习模式，问答式反馈很有成就感，讲解也通俗易懂，可以当在线家教用——但仍然是「一次问答」，不是一套能接着往下写、能验证、能复习的东西。

其实想要的形态很具体：**给出一个主题，能吐出一份可以按部分续写、能真的跑通、还能回头复习的动手实践教程**。为了找这种东西把各家 agent 工具试了一圈，问了各种 AI「有没有办法系统地通过做项目学一个方向」，得到的都是「给你列十个项目」，就没有一个系统性的东西。

### Lathe 是对的东西，但它前面还有一道门槛

直到有天逛 [Zeli](https://zeli.app/zh) 遇到了 [Lathe](https://github.com/devenjarvis/lathe) 这个项目（再次感谢编写这个项目的大佬🙏），看了介绍惊为天人😲——这就是我要找的东西，而且它把「怎么把技术讲透」的规则本身也写得极其完整。于是又开始问各种 AI：这个工具在国内有什么好的使用媒介。

最初的想法是用 DeepSeek v4 相关的工具（因为便宜😁）直接配合 Lathe 仓库里的使用教程，结果操作起来挺麻烦：Lathe 那套流程要自己跑起来，模型接入还得单独解决，规则靠人工一段一段贴给 agent，产物存在哪、下一部分怎么接、验证结果怎么记，全靠自己维持。就想着能不能把它提炼成 skills 让 AI 用——**让终端 Agent 自己充当执行引擎**，不需要额外的命令行工具，只要客户端支持 Agent Skills 这套布局（`SKILL.md` + 按需加载的 `references/` 模块），规则、目录结构、检查脚本全都打包在技能目录里带着走。先让 AI 照着他的源码改写出了初版（Qwen 3.7max），之后再一版一版自己用着改。

载体选择了当时有免费额度的 QoderWork：能用，操作比较方便，还能直接查看生成的教程。也正因为技能就是一堆 Markdown 加纯标准库的 Python 脚本，它没有锁死在某一个客户端上——换到 Reasonix 这类支持同样标准的终端 Agent，只是复制一下目录的事。

### 为什么到现在还在改

因为它是拿来干活的工具，不是 demo，用多了总会发现一些问题和可优化的点。更要紧的是，这类技能「规则写得对不对」没法靠读一遍文本判断，只能**真实跑一遍再机械审计产出**——本仓库大半的改动都来自「让另一个 agent 在隔离上下文里独立执行一次，然后逐条核对它留下的日志与文件」，上面 v0.6.0 那一节后半段的改动就是这么来的。

目前（2026-10-25）的情况是：9 月初失业，原本的学习节奏断掉了，转而用这个 skill 去整理和学习其他方向的知识，所以 skill 最近反而一直在更新——新场景又翻出一轮新问题。不过吧！还是期望能尽快找到工作😤。
