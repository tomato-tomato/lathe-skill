# Lathe 技能使用教程

Lathe 是一套面向 LLM 编码助手的**动手实践型教程生成技能体系**。通过一个统一的 `/lathe` 命令，你可以按需生成高质量的技术教程，并逐步续写、验证、提问和管理。

> 本文对应技能版本 **v0.6.0**。版本号可从三处确认：`lathe/SKILL.md` 的 frontmatter `version:` 字段、正文顶部的“技能版本”行，以及运行 `/lathe 列表` 时输出末尾的版本行；每个教程 `metadata.json` 的 `lathe_version` 字段也记录了生成/续写它时所用的版本。
>
> **v0.5.3 的新增能力：面试文档**——`/lathe 面试 <slug> [part-NN]` 可为教程生成「按 Part 分章的面试要点文档」，并可从**生成 / 复习 / 续写**三条路径产出与自动同步（详见 [/lathe 面试 — 面试文档](#lathe-面试--面试文档)）。同版还包括若干生成提速与加载精简的改动（研究分级触发、预检/自检去重、配额前置、加载精简等），**不影响已有教程**。
>
> **v0.5.3.1 的优化：配额矩阵与主题新颖度**——新增 `topic_novelty`（全新/相邻/熟悉）、`course_plan`（课程路线图）和 `continuity.open_threads`；检索预算、地基章节、标注、概念锚定按主题新颖度自适应；continuity 扩到 1200 字软上限 / 2000 字硬上限。新主题会多讲地基和陷阱，熟悉主题保持精简。**旧教程无需迁移**，缺失字段按规则推断并在此后续写时补上。
>
> **v0.5.4 的优化：讲透优先 + 验证/续写补强**——配额只约束知识点数量，不再限制解释长度、类比句数、标注总数或代码行数；代码块区分 `runnable` / `fragment` / `exercise` / `text` / `output` / `expected_failure`；验证支持增量/全量、改动面预检、代码块结构预检、级联失效与预期失败；续写强制核对下一部分契约与 `course_plan`，并自查旧接口签名。新增 `changed_interfaces`、`open_threads` 归档、未验证横幅与 `_needs_backfill`；单部分正文/单块过大时优先拆分，不压缩解释。**旧教程无需强制迁移**；未标记代码块仍按 `runnable` 处理，旧片段/`...` 若被验证误判，补 `fragment` 标记即可。
>
> **v0.6.0 的优化：知识点不再无声消失**（原 0.5.5 分支的改动并入本版本，0.5.5 不单独发布）。要点：
>
> - **练习承接 + 积压治理**：练习不再限制「能否引入新概念」，而是要求每道题按**三档分流**：档 1 融进本部分对应知识点（须有「疑问复述 + 解释 + 可运行验证」三件套）、档 2 进**承接章节**（≤1 章、≤2 条，不占 4-7 但计入总章 ≤9）、档 3 顺延进 `knowledge_backlog`。用户直接列知识点时先**归一化**（每条一个可命名的产出、保留原文编号），再按**名额分配表**决定本部分讲哪几条：积压越多，分给还债的位置越多（0/2/3/4）。`knowledge_backlog` 上限 14 条（2 个 Part 的量），触到闸门时给出「扩 Part / 降级自学清单 / 缩减」三选一，不再静默堆积；积压成规模时输出重规划草案，**用户确认后才改 `course_plan`**。被延后的知识点必须在**正文里留提醒**（题面斜体 / 承接章末尾 / 本部分不覆盖），只写 metadata 不算。**读取端也已补齐**：`/lathe 列表` 显示积压条数、`/lathe 复习` 单列「还没讲到的（按 ID）」并读取被归档的概念、`/lathe 续写 收尾` 用门禁拦住「带债完结」。**旧教程无需迁移**：`exercise_carry`、`knowledge_backlog` 缺失即视为空。
> - **知识点账本 `syllabus.json`**：每个知识点一行一条记录，六种状态（`planned` / `queued` / `taught` / `self-study` / `dropped_by_user` / `duplicate`），状态只改不删；`knowledge_backlog` 是其中 `queued` 的投影，`metadata.syllabus_ids` 是 ID 镜像（条目被整条删掉时能指出缺哪个）。生成时先确认整门课大纲；复习、列表、收尾门禁都按账本对账；旧教程首次续写时按正文回填（不改旧部分）。
> - **写前计划确认 + 覆盖回执**：列了知识点、有顺延/去重/闸门时，动笔前先确认计划；交付时附对账等式与「知识点 → 章节」回执。去重只丢「语义完全相同」的，部分重叠改为「深化：」条目；积压闸门默认 ① 扩 Part，降级与删减只能由你显式选择。
> - **练习新概念上限**：必做题最多 2 道引入新概念；选做题可以引入，但要附线索与官方文档入口，不入积压。
> - **交付前试跑 + 自带检查脚本**：技能新增 `scripts/`（`part_lint.py` 结构检查、`trial_run.py` 逐块编译运行、`ledger_check.py` 账本对账，纯标准库 Python 3）。有 shell 时落盘前必须跑，回执里的章数、试跑结果、覆盖行直接粘贴脚本输出（真实验证中模型自己填的章数填错过、19 个代码块有 5 个有缺陷）。
> - **规则收拢**：账本、积压、确认、回执、练习承接的规则集中到新文件 `references/knowledge-ledger.md`，其他文件只引用；续写一次加载的规则从 135.8 KB 降到 125.0 KB。
> - **其他**：`changed_interfaces.supersedes` 登记被后续契约作废的旧检查点（验证记 `historical`，旧部分保持 `passed`）；`/lathe 提问` 发现错误时给出勘误确认块，你回复编号或「确认修改」/「只记勘误」才处理；`mermaid` 等图表块不再被当作可执行步骤；若干规则矛盾的勘误。
>
> **旧教程无需迁移**：新字段缺失即视为空；首次续写会请你确认账本回填结果。

> 本教程适用于 **QoderWork** 或 **QoderWork CN** 桌面客户端。本仓库中的技能在这两款客户端中使用过；技能采用标准 Agent Skills 布局（SKILL.md + references/ 子目录），也已确认兼容 Reasonix 等支持该标准的终端 Agent（见[常见问题](#常见问题)），其他场景需要注意验证

## 快速开始

### 1. 下载技能包

从本仓库的 [GitHub Releases] 页面下载最新的 `skills` 压缩包并解压：

```bash
# 下载并解压（以实际 release 文件名为准，如 lathe-0.6.0.zip）
unzip lathe-0.6.0.zip -d ./skills-download
```

解压后的目录结构如下：

```
skills-download/
└── lathe/                          ← 统一技能文件夹
    ├── SKILL.md                     ← 入口路由 + 共享配置（含版本号）
    └── references/                  ← 模块（按需加载，请勿单独移动）
        ├── writing-core.md          ← 写作核心（共享：结构/配额矩阵/标注/不变量/研究纪律）
        ├── metadata.md              ← metadata.json 规范（共享：字段/continuity/course_plan/自愈）
        ├── style-benchmarks.md      ← 风格标杆（共享：仅生成时选定主锚点）
        ├── generate.md              ← 生成教程模块
        ├── extend.md                ← 续写 / 收尾模块
        ├── review.md                ← 复习模块
        ├── interview.md             ← 面试文档模块
        ├── verify.md                ← 验证模块
        ├── ask.md                   ← 提问模块
        ├── tag.md                   ← 标签模块
        ├── voice.md                 ← 语气模块
        ├── scan.md                  ← 扫描登记模块
        └── list.md                  ← 列表模块
```

> `references/` 下的前三个文件是**共享模块**（多个操作引用的单一事实源），其余为每项操作各自的协议文件。它们均**按需加载**：例如列表、提问、扫描不会读取 `writing-core.md`，续写不会读取 `style-benchmarks.md`。

> 压缩包内仅包含 `lathe/` 技能文件夹本身；本使用教程不随包分发，可在本仓库的 `docs/skills-tutorial.md` 查阅。

> **提示：** 安装时必须连同 `references/` 子目录一起复制——它是技能的标准布局（Anthropic Agent Skills 规范），模块文件按需加载，能减少每次调用的上下文开销。

### 2. 安装技能

将解压后的技能文件夹复制到技能目录：

```bash
# 复制到用户级技能目录（所有项目可用，推荐）
cp -r skills-download/lathe ~/.qoderwork/skills/

# 或复制到项目级技能目录（仅当前项目可用）
mkdir -p .qoderwork/skills
cp -r skills-download/lathe .qoderwork/skills/
```

> **提示：** 用户级安装（`~/.qoderwork/skills/`）只需操作一次，之后在所有项目中都可使用这些技能。
>
> 本仓库中的技能已在 QoderWork 和 QoderWork CN 客户端上测试；如需在 Reasonix 中使用，将 `lathe/` 目录复制到 `~/.reasonix/skills/` 即可（见[常见问题](#常见问题)）。

### 3. 验证安装

在 QoderWork 或 QoderWork CN 客户端中输入 `/lathe`，如果技能正确加载，AI 会展示操作选项供你选择。

### 4. 生成第一个教程

```
/lathe 用 Go 构建一个 Raft 共识算法实现
```

AI 会引导你完成：确认保存位置与经验水平 → 锁定工具版本 → 研究主题 → 生成第一部分 → 自动存储。

## 操作一览

所有操作通过 `/lathe` 调用，后跟**意图关键词**（中文或英文均可）和参数：

| 操作 | 命令 | 功能 | 写入文件 |
|------|------|------|----------|
| **生成教程** | `/lathe <主题>` | 生成教程的第一部分 | `part-01.md`、`metadata.json`、在 `~/.lathe/config.json` 登记位置 |
| **续写教程** | `/lathe 续写\|extend <slug> [指导]` | 为已有教程添加下一部分（**该教程已有面试文档时会自动同步本部分**） | `part-NN.md`、更新 `metadata.json`；已有面试文档时追加一个分段 |
| **收尾完结** | `/lathe 续写 收尾 <slug>` | 生成总结部分并完结课程（`status` 置为 `completed`） | 总结 `part-NN.md`、更新 `metadata.json` |
| **复习教程** | `/lathe 复习\|review <slug>` | 生成复习材料（不改变课程方向与状态） | `part-NN-review.md`、更新 `metadata.json` |
| **面试文档** | `/lathe 面试\|interview <slug> [part-NN]` | 生成或补齐面试要点文档（一个 slug 一个文件，按 Part 分章） | `<slug>.md`（或 `interview.md`）、首次创建时登记 `interview_paths` |
| **验证教程** | `/lathe 验证\|verify <slug>` | 端到端验证教程是否可用，含版本冲突检测与修复；工作区持久化并增量复用 | `verify-result.json`、`.lathe-verify/` 工作区、同步 `metadata.json` 状态；版本冲突修复经确认后可改 `part-NN.md` |
| **提问内容** | `/lathe 提问\|ask <slug> [part] <问题>` | 回答关于教程某部分的问题（part 可省略，自动定位）；发现错误时给出勘误确认块 | 默认无；你确认勘误后修改对应片段并记入 `research.md` 的 `## Errata` |
| **管理标签** | `/lathe 标签\|tag <slug>` | 管理教程的搜索标签 | 更新 `metadata.json` |
| **创建语气** | `/lathe 语气\|voice [名称]` | 创建自定义写作语气预设 | `voices/<名称>.md` |
| **扫描登记** | `/lathe 扫描\|scan [目录]` | 把磁盘上未被识别的教程登记进来，并清理失效条目 | 仅 `~/.lathe/config.json` |
| **列出教程** | `/lathe 列表\|list [slug]` | 按语言分组列出所有教程，或查看某教程详情 | 无（只读） |

> **提示：** 也支持纯自然语言触发（无需 `/lathe`），AI 会自动识别意图。中文和英文关键词均可识别。当意图不明确时，AI 会展示选项菜单供你选择。

## 存储路径配置

教程存储位置记录在配置文件中，支持**多路径存储**——不同教程可以保存在不同目录：

**配置文件位置：** `~/.lathe/config.json`

```json
{
  "tutorials_base_path": "~/others/lathe_tutorials",
  "tutorial_paths": {
    "taskr": "~/others/lathe_tutorials",
    "raft-go": "~/projects/my-tutorials"
  }
}
```

| 字段 | 含义 |
|------|------|
| `tutorials_base_path` | 默认基础目录：生成新教程时默认提议的位置；`voices/` 自定义语气目录也始终位于此处 |
| `tutorial_paths` | 每个教程（slug）实际所在目录的映射，由技能自动维护 |

### 首次使用 / 配置文件缺失

调用 `/lathe` 时若配置文件不存在，技能会询问你是第一次使用还是之前已经生成过教程：

- **第一次使用：** 询问是否使用默认路径 `~/others/lathe_tutorials/`（或指定新路径），确认后自动创建配置文件。
- **已经使用过：** 请提供已有教程的存放位置（可以是一个或多个目录）。技能会按扫描规则枚举这些位置、分类展示结果，经你确认后写入配置——这样分散在各处的教程都能被 `列表`/`续写`/`验证` 等命令找到。
- **已存在配置：** 静默读取，直接使用。

> ⚠️ **注意：上述“已经使用过”分支只在配置文件不存在时触发。** 配置建立之后新出现的教程（手工拷贝、`git clone` 拉下来、目录被移动、跳机器同步）不会自动被发现——要把它们找回来，用 [`/lathe 扫描`](#lathe-扫描--扫描登记教程)。

### 生成时的保存位置

每次生成新教程时，技能会询问本课程保存位置（默认提议 `tutorials_base_path`）。选择默认则与旧行为一致；指定新路径则该教程单独存到那里，并自动登记到 `tutorial_paths`。

### 修改存储配置

直接编辑配置文件即可：

```bash
# 查看当前配置
cat ~/.lathe/config.json

# 修改默认目录（新教程的默认提议位置）
echo '{"tutorials_base_path": "~/my-tutorials", "tutorial_paths": {}}' > ~/.lathe/config.json
```

> 修改 `tutorials_base_path` 后已有教程不会自动迁移，但 `tutorial_paths` 中已登记的教程仍可在原位置被找到——这正是多路径机制的优势。

### 面试文档的存储位置

面试文档（见 [/lathe 面试 — 面试文档](#lathe-面试--面试文档)）的位置用**另外两个可选字段**记录，与教程路径解耦：

```json
{
  "interview_base_path": "~/Code/agent-transition/interview",
  "interview_paths": {
    "nest-kb-service": "~/Code/agent-transition/interview/阶段一_NestJS与服务端基础"
  }
}
```

| 顺序 | 条件 | 文档路径 |
|------|------|----------|
| 1 | `interview_paths[<slug>]` 存在 | `<该目录>/<slug>.md` |
| 2 | `interview_base_path` 存在 | `<该目录>/<slug>.md` |
| 3 | 都没有 | `<教程目录>/<slug>/interview.md` |

**一个 slug 一个文档，文件名 = slug**（第 3 档落在教程目录内，故用 `interview.md`）。

**位置确认规则：**

- **文档不存在**（首次创建）→ 技能**会询问**：展示解析出的默认路径并确认；你给出新位置则写到那里，并登记到 `interview_paths`。
- **文档已存在** → **不询问**，沿用当前位置，只在结果里播报路径。
- 你也可以随时直接编辑 `interview_paths` 把文档挪到别处。

> 两个字段都可选，旧配置缺失即走第 3 档，**无需迁移**。

### 操作已有教程时的位置解析

对已有教程执行操作（续写、验证、复习、提问、标签等）时，技能按以下顺序定位它的实际目录：

1. 先查 `tutorial_paths[<slug>]` 中登记的位置；
2. 未登记则回退到默认目录 `tutorials_base_path`；
3. 该位置也找不到此 slug 时，列出配置中已知的所有 slug 及其位置供你选择，并提示可用 `/lathe 扫描` 把未登记的教程找回来。

### 默认目录结构

```
~/others/lathe_tutorials/          ← 默认教程基础目录
├── <slug>/                        ← 每个教程一个子目录（也可位于其他已登记目录）
│   ├── metadata.json              ← 教程索引（顶部含防误删提醒，请勿删除；误删可自愈重建）
│   ├── syllabus.json              ← 知识点账本（每个知识点一条，讲到哪、欠着什么；请勿手工删条目）
│   ├── part-01.md                 ← 第一部分
│   ├── part-02.md                 ← 第二部分（由 /lathe 续写 添加）
│   ├── research.md                ← 可选归档（接口变更 / 未决问题 / 已讲概念 / 自学清单 / 勘误）
│   ├── verify-result.json         ← 验证结果（由 /lathe 验证 生成）
│   └── .lathe-verify/             ← 验证工作区（隐藏目录，首次验证后自动创建，可安全删除）
└── voices/                        ← 自定义语气预设（始终位于默认基础目录）
    └── <名称>.md                  ← voice 规范文件
```

> ⚠️ **请勿删除 `metadata.json`**——它是教程的索引文件。若误删或损坏，技能会在下次操作时自动检测到并从 `part-*.md` 正文重建（重建前会展示推断结果请你确认）。

## /lathe — 生成教程

### 功能

为任意编程主题生成动手实践型教程的第一部分。这是整个技能体系的核心入口。

### 调用方式

```
/lathe <主题描述>
```

**示例：**

```
/lathe 用 Zig 构建数字合成器
/lathe 用 Rust 实现一个键值存储
/lathe 用 Go 构建 Raft 共识算法
```

### 工作流程

调用后，AI 会按以下步骤引导你：

**1. 解析配置**
自动从 `~/.lathe/config.json` 读取配置。配置缺失时会询问你是第一次使用还是已生成过教程：第一次使用确认默认目录；已使用过则提供已有教程位置（可多个），技能扫描验证后写入配置（见[存储路径配置](#存储路径配置)）。

**2. 一轮分组提问**

AI 用**一条消息**集中收集写作前需要的全部信息，不再多轮往返：

- **保存位置（每次生成都问）**：默认提议配置中的默认目录，可指定其他路径。这一项**必问**：即使在没有图形选择框的终端 Agent（如 Reasonix、Claude Code、Codex）里，AI 也会以纯文本形式问出，回车即采用默认目录
- **教程 slug**：AI 会由主题推导一个 kebab-case 短名称并**展示给你确认**——它是目录名和教程的永久标识，你此后靠它调用其他所有操作
- **经验水平**：初学者、有一定了解、还是相关领域有经验？（记录为 `experience_level`，后续续写直接沿用，不再重复询问）
- **主题新颖度**：这个主题对你是全新领域、有相邻经验、还是已经熟悉？（记录为 `topic_novelty`，默认按经验水平推断；它决定检索预算、地基章节、标注与概念锚定的深度）
- **语气（voice）**：列出可选语气供你选择——`plainspoken`（默认，平实精确）、`companion`（陪伴式）、`craftsman`（工匠式），或你用 `/lathe 语气` 创建的自定义 voice。不选即用默认 `plainspoken`（此时不加载任何额外文件）；选了非默认项才会按需加载对应规范
- **澄清问题**（仅在主题宽泛时出现，最多一个）
- **仓库**：是否针对特定代码仓库（URL 和分支）
- **工具链版本与学习目标**：如 *"我将基于 **Go 1.22** 来写——可以吗？"*；同时 AI 会基于主题与你的回答提炼一句可评估的**学习目标**（`goal`）一并请你确认——它是后续续写时"目标达成回顾"与收尾完结的判定基准

对某项未作答时，AI 会采用合理默认值并告知，不再追问。

**3. slug 与目录冲突检查（写作之前）**

确认 slug 后、开始研究之前，AI 会检查保存位置下是否已存在同名目录。**已存在时绝不覆盖**，而是先识别它是什么（标题、部分数、状态），然后给你三个选项：换一个 slug 新建 / 改为续写那个教程 / 取消。

> 相近主题（如"用 Rust 写 CLI 工具"与"Rust 命令行应用"）极易推导出同一个 slug，这道检查避开了覆盖已有教程的风险。若该 slug 已登记在**其他**目录，AI 也会一并告知（可能是教程被移动过，可用 `/lathe 扫描` 校正登记）。

**4. 确定教程语言**
教程正文语言默认跟随你的对话语言，也可显式指定（如"用英文写"），结果记录在 `metadata.json` 的 `language` 字段，后续续写/提问自动沿用。

**5. 选定风格主锚点**
按主题匹配一位标杆作者作为主锚点（如分布式系统 → `sam-who`、编译器 → `nystrom`），其 id 记入 `metadata.json` 的 `style_anchor` 字段。后续续写直接沿用该 id，不再重新加载风格标杆表——既保证节奏一致，也节省开销。

**6. 研究主题**
AI 会通过网络搜索查阅权威来源（官方文档、论文、源代码等），确保教程内容基于真实资料而非模型记忆。研究采用**摘要优先**策略：先从搜索结果标题与摘要中提取事实，只有摘要不足以支撑某个关键事实时才做定向全文抓取；**检索预算按主题新颖度分级**——熟悉 3 次搜索 / 1-2 次抓取，相邻 5 / 3，全新 8 / 5-6（1 次搜索可携带 1-4 条 query，来源条数不设上限）。**每个部分至少打开/确认 3 个实际来源，其中至少 1 个官方/一手来源；搜索调用数不等于来源数。** 来源优先级：官方文档/规范/RFC/源码/changelog > 高质量独立文章/论文 > 博客/问答；关键事实要能对应到来源，没有来源就标 `[!UNVERIFIED]`。**生成与续写适用同一套预算**。同时执行**版本-特性一致性检查**：示例代码使用的特性必须在锁定版本下成立（如 Rust edition 与代码语义匹配），不确定时查官方 changelog。

> 如果当前会话没有网络工具，AI 会提前告知，并在关键声明处标记 `[!UNVERIFIED]`。

**7. 生成第一部分**
AI 在内部完成预检（选择控制性示例、确定章节结构与 `course_plan`、校验版本-特性一致性等）后，撰写 `part-01.md`，在 H1 之后写入“未验证”状态横幅，在检查点后写“本部分结束时的文件状态”，在“接下来”中写“下一部分起始状态”，然后按**配额矩阵**执行**交付前自检**（六项讲透、代码完整性、知识点数量、练习/来源/版本/术语/一致性等）。

> **写前计划确认（生成时总会有这一轮）：** 研究之后、动笔之前，AI 把 `course_plan`、**每一项的大纲知识点**（3-7 个，后续项是预估）、清单归一化对照（你列了知识点时）和 part-01 的知识点计划发给你确认；你回复「可以」或改完计划后才开始写。确认过的大纲写进知识点账本 `syllabus.json`，是后面判断「课程有没有讲全」的基准，所以这一轮不能用「直接写」跳过。你给的是整门课的清单时，属于后续部分的条目会记为 `planned`（按大纲轮到再讲），不会挤进积压。

**8. 存储教程**
将 `part-01.md`、`metadata.json` 和 `syllabus.json`（知识点账本）写入你确认的保存位置，并在 `~/.lathe/config.json` 的 `tutorial_paths` 中登记该教程位置，然后告知你（最前面是积压对账与**覆盖回执**——哪个知识点讲在哪一节、哪些顺延、计划章数与实写章数是否一致）：

> 积压：上次 0 + 新入 2 − 本次讲 0 − 降级 0 = 现在 2 条（core 2）；自学清单 0 条。
> 覆盖回执：本部分覆盖 1a→§1 ✅ · 1b→§2 ✅ … ｜ 本次顺延 1c、1d → 积压（预计 Part 2）｜ 章节完整性：计划 5 章 / 实写 5 章 ｜ 账本：taught 5 · queued 2 · planned 31（共 38 条）
> **教程已保存**到 `~/others/lathe_tutorials/raft-go/`。
> 这是第一部分。要添加更多部分，调用 `/lathe 续写 raft-go`。
> 验证是可选的：调用 `/lathe 验证 raft-go`。无论是否验证，代码都必须完整；验证只执行 `runnable` / `expected_failure` 块和检查点，跳过片段/练习/文本块。
> 要对某个部分提问，调用 `/lathe 提问 raft-go part-01.md`。

### 教程质量标准

每篇教程遵循以下标准：

- **控制性示例：** 贯穿始终的具体产物（如"一个 4 声部减法合成器"），不使用 `foo`/`bar`
- **概念锚定：** 重要概念除详细介绍外，还会从你已知的知识体系引申讲解（锚点随你回答的经验水平调整），帮助更快理解
- **自适应深度：** 生成时会记录主题新颖度（全新 / 相邻 / 熟悉），据此调整检索预算、地基章节和陷阱密度；配额只约束知识点数量，不限制每个知识点的解释长度、类比或代码行数——新主题会多讲地基和陷阱，熟悉主题保持精简，但都不会为配额删掉必要解释
- **讲透优先：** 每个构建节讲清定义、动机、用法、例子、边界和可观察的验证结果；需要类比、对照或展开时就写，不因篇幅配额删减
- **覆盖与一致性：** 每个核心知识点至少有一个练习或可观察结果；代码中的符号、数字、API 与正文及 `fixed_numbers` 一致
- **代码完整性：** 代码块按 `runnable` / `fragment` / `exercise` / `text` / `output` / `expected_failure` 标记；运行必需代码不得用 `...` 省略；修改 API/签名时给出改动面表，并至少有一个集成检查点；跨部分接口变化同步到 `changed_interfaces`，**让旧检查点字面失配的变更还要登记 `supersedes`**（见下文验证说明）
- **篇幅不是上限：** 知识点讲透了写多长都可以接受，长不是缺陷。是否拆部分只看「独立学习里程碑 / 独立改动面 / 能否一次学完」，**不看字数**；正文约 10,000 中文字符、单个 `runnable` 约 100–120 行只是参考观察值，不是阈值。大代码按文件/逻辑段**分段呈现**、测试单独成块，但不裁内容，也不为压低篇幅删解释
- **交付前试跑与脚本检查：** 有 shell 时，落盘前在系统临时目录里用技能自带脚本检查本部分——`part_lint.py`（结构、代码块类型、练习上限、实写章数）、`trial_run.py --run`（逐块编译运行 `runnable` / `expected_failure`）、`ledger_check.py`（账本对账）；检查点命令在同一临时目录手动补跑。不用 `.lathe-verify/`、不碰你的项目、不改验证状态；数字以实际运行为准，回执里的章数与试跑结果直接取脚本输出；跑不了的在回执里写明原因
- **自检效率：** 每节一次六项检查，最多两轮；第 2 轮只查跨章节项和修复点，不反复全文通读
- **最终状态：** 每部分列出新增/修改文件、“下一部分起始状态”和“本部分不覆盖”，降低读者拼装和续写漂移
- **具体数字：** 采样率、缓冲区大小、页面大小等，避免模糊的"很快"/"很大"
- **内联引用：** 关键事实旁直接附上来源链接
- **检查点：** 每个部分末尾有可执行的验证命令和预期输出
- **标注系统：** 使用 `> [!PREDICT]`、`> [!RECALL]`、`> [!HEADS-UP]` 等标注增强学习效果；标注按需使用，不设总数上限，`ASIDE` 仍是装饰性旁白（每部分 ≤2 个）
- **风格标杆：** 根据主题场景匹配一位主锚点标杆作者（如 Raft 类分布式系统 → Sam Who、编译器 → Robert Nystrom、Rust 语言 → The Rust Book 作者），侧重其长项指导写作节奏与章节结构；风格锚点不覆盖讲透原则，完整标杆体系见技能包内的 `references/style-benchmarks.md`

## /lathe 续写 — 续写教程

### 功能

为已有教程添加下一部分。新部分会继承教程的控制性示例、数字、语气和工具版本。

### 调用方式

```
/lathe 续写 <slug> [指导...]
# 或使用英文关键词
/lathe extend <slug> [指导...]
```

**示例：**

```
/lathe 续写 raft-go
/lathe extend raft-go
/lathe 续写 raft-go 这一部分实现日志复制
/lathe extend raft-go 这一部分实现日志复制
/lathe 续写 digital-synth-zig 添加低通滤波器
```

如果不提供指导，AI 会根据上一部分末尾的"接下来"方向自动延续。

### 工作流程

1. **吸收现有教程（按需读取）** — 先读 `metadata.json`，其中的 **`continuity` 连续性摘要**承载了控制性示例、固定数字、隐喻状态、已讲透的概念、上一部分的前向钩子和各部分标题。摘要新鲜时，**只需再读最后一个部分的全文**即可动笔，历史部分不再重读；同时对照 `goal` 评估达成度

   > 旧教程首次续写（或你手工改过旧部分）时没有可用摘要，AI 会全文读取一次并建立 `continuity`——这是**一次性成本**，此后该教程再也不需要全文重读。教程越长（一个 5 部分教程的正文可达 10 万字符），这项优化省下的开销越可观。

2. **从 metadata 取齐写作约束** — voice、正文语言、风格锚点（`style_anchor`）、读者水平（`experience_level`）、主题新颖度（`topic_novelty`）、课程路线图（`course_plan`）、工具版本全部从 `metadata.json` 承继，**不重新询问、不漂移**；旧教程缺少的字段按已有内容推断并在本次写回时补上
   - **起点契约：** 写前读取最后一部分的“下一部分起始状态/本部分不覆盖”，与 `next_hook` 冲突时以正文契约为准；核对 `course_plan` 的下一个未完成项，偏离时更新并说明，不静默跳项
   - **旧签名自查：** 写前/写后对活跃 `changed_interfaces.from` 做 grep；新 `runnable` 代码不得出现旧签名，展示旧版本必须用 `fragment` 并标注
3. **确认本地项目路径（可选）** — 如果你的教程涉及实战项目（如命令行工具、Web 应用等）：
   - **`local_project_path` 已有记录** — 只做一次轻确认（回车沿用 / 输入新路径 / 回复"跳过"），不从零询问
   - **首次询问** — 提供路径则 AI 读取你当前的代码状态，基于实际进度续写；跳过则基于教程中描述的代码状态续写

   > 路径会记录到 `metadata.json` 的 `local_project_path` 字段，后续续写直接复用。

   **3b. 写前计划确认（满足条件时）** — 你在指令里列了知识点，或本部分会有条目顺延、去重合并、触发积压闸门，或本部分的大纲知识点需要增删，或旧教程第一次建知识点账本时，AI 会和上面的路径确认合并成**一条消息**，把本部分计划发给你：

   ```
   写前计划确认（part-04）
   ① 清单归一化：3「鉴权」→ 3a bcrypt 的 salt 与 cost ｜ 3b JWT payload 放什么 ｜ 3c Guard 的位置
   ② 本部分讲（名额 7 = 还债 2 + 新清单 5）：K-1、K-2、3a、3b、4、5、6
   ③ 顺延入积压：3c、7（预计 Part 5）
   ④ 去重/合并：「JWT 签名」部分重叠已讲 part-02「JWT 结构」→ 入队为「深化：JWT 签名算法选择」（未丢弃）
   ⑤ 闸门：（仅触发时）三选一，默认 ① 扩 Part
   回复「可以」按此执行；也可以直接改。
   ```

   去重只在「和已讲内容语义完全相同」时才不入队；部分重叠的会改成「深化：」新条目，拿不准按不同条目处理。积压满 14 条时默认 **① 扩 Part**（附新的 `course_plan` 草案），**降级到自学清单（②）或删减（③）只能由你显式选择**。不想多这一轮时，在指令里写「直接写」或 `--no-confirm`，计划内容会照常出现在交付后的覆盖回执里。

4. **研究新内容** — 与 `/lathe` 相同的纪律和**按 `topic_novelty` 分级的检索预算**（熟悉 3 / 相邻 5 / 全新 8 次搜索，抓取相应为 1-2 / 3 / 5-6；1 次搜索可带多条 query）；**只研究本部分新引入的内容**，已有部分建立的事实直接沿用，并优先复用 `metadata.sources`
5. **确定部分编号** — 自动递增（如已有 `part-01.md`，下一个是 `part-02.md`；已有复习材料时在其最大编号后递增）
6. **写入新部分** — 在 H1 之后写入“未验证”状态横幅，然后遵循完整的教程结构，以 `> [!RECALL]` 间隔检索开头；并在 `## 接下来` 前插入 **`## 目标达成回顾`** 小节：陈述原定学习目标、已覆盖/未覆盖内容、达成结论——由你自行判断继续延伸还是收尾完结；写完执行交付前自检
7. **更新 metadata.json** — 追加新部分到 `parts` 数组，追加新来源，**增量更新 `continuity` 摘要**（下次续写的成本基础，不可省；总量 1200 字软上限 / 2000 字硬上限是索引预算，不是正文预算，`covered_concepts` 只追加不合并，`open_threads` 每条 ≤80 字，已解决/溢出归档到 `research.md`），同步更新 `course_plan` 与 `changed_interfaces`，`lathe_version` 更新为当前技能版本，`status` 重置为 `unverified`（若课程已完结，此操作自动撤销完结、重新开放）
8. **报告完成** — 结果最前面是积压对账等式（`上次 a + 新入 b − 本次讲 c − 降级 e = 现在 f`）和**覆盖回执**（每个知识点讲在哪一节、哪些顺延、去重了什么、计划章数 / 实写章数）；写前计划里的每一条都必须在回执里有着落，对不上的 AI 必须补写或入队后才交付。随后告知你如何查看和验证

### 目标达成与收尾完结

生成教程时会确认一个**学习目标**（`metadata.json` 的 `goal` 字段；旧教程首次续写时自动推断补上）。每次续写都会对照目标评估达成度并写入新部分，你可以随时选择收尾：

```
/lathe 续写 收尾 <slug>
```

收尾模式生成一个**总结部分**：全课程逐部分回顾、知识图谱（Mermaid）、目标对照、练习方向、寄语，以及一段回顾自检问题。总结里还会单列**未讲清单**（谁没讲、为什么、想学时怎么捡回）。

收尾前（写总结之前）有一道**门禁**：知识点账本 `syllabus.json` 里不能还有 `queued`（欠着的）或 `planned`（大纲还没轮到的）条目，除非每一条都已由你显式降级到 `research.md` 的 `## Self-study Backlog`；`course_plan` 的每一项都必须有对应 Part。任一条不满足时，AI 会列出缺口并让你三选一——① 补写一个 Part；② 逐条降级到自学清单；③ 强制完结（总结里如实写明未覆盖项）。**你确认之前不会把 `status` 置为 `completed`**。门禁通过后 `status` 标记为 `completed`，`/lathe 列表` 中显示 ⭐ 已完结。

> 完结不是永久的：之后直接 `/lathe 续写 <slug>` 即可重新开放课程（`status` 自动重置）；`/lathe 复习 <slug>` 则不会改变完结状态。

### 注意事项

- 每次只写一个部分，不批量生成
- 不修改已有的部分文件
- 继承相同的工具版本，不静默升级
- 如果读者想迁移到新版本，建议创建新教程而非在原教程中漂移

## /lathe 复习 — 复习教程

### 功能

为久未学习、想先复习再精进的读者生成结构化复习材料。复习不引入新内容、不改变课程方向，也不影响课程状态（已完结的课程复习后仍保持完结）。

### 调用方式

```
/lathe 复习 <slug>
# 或使用英文关键词
/lathe review <slug>
```

### 复习材料

生成文件命名为**最新部分编号 + 1 并附 `-review` 后缀**（如已有 part-01~03，则生成 `part-04-review.md`），包含：

- **逐部分回顾** — 每部分构建了什么、核心概念、关键数字；
- **自测：间隔检索** — 5-8 个不给答案的问题，覆盖各部分关键概念；
- **重跑检查点** — 摘录各部分检查点命令与预期输出，供本地重执行；
- **学习目标回顾** — 对照 `goal` 说明已建立的能力；
- **还没讲到的（按 ID）** — 有知识点账本时，按 `syllabus.json` 列出所有还没讲的条目（欠着的 `queued` → 大纲还没轮到的 `planned` → 你选择自学的 `self-study` → 你删掉的 `dropped_by_user`），写清为什么没讲、计划何时讲，末尾附账本各状态条数；旧教程没有账本时按 `knowledge_backlog` 与自学清单列出；全部讲完时明确写「无」，不省略；
- **还可以继续深入的方向** — 3-5 个延伸方向，想继续时直接 `/lathe 续写 <slug>`。

复习会读 `knowledge_backlog`、`continuity.exercise_carry`，以及 `research.md` 的 `## Open Threads Archive`、`## Changed Interfaces Archive`、`## Self-study Backlog`、`## Covered Concepts Archive`——**归档过的概念仍然算在覆盖范围内**，不会因为索引瘦身而从复习里消失。复习材料计入 `parts` 但不参与验证（`/lathe 验证` 会跳过 `-review` 文件），`/lathe 列表` 中标注 *（复习）*。

## /lathe 面试 — 面试文档

### 功能

为教程生成**面试要点文档**：**一个 slug 一个 Markdown 文件**，按**教学部分（Part）分章**，每条要点给出「一句话回答 → 展开 → 追问点 → 我的项目里」的解答，方便面试前突击复习。

与「复习材料」的区别：复习材料（`part-NN-review.md`）是**课程内的回顾**；面试文档是**课程外的独立文件**，按 slug 命名、按 Part 分章、面向面试表达组织。

### 调用方式

```
/lathe 面试 <slug>                  # 整门课程（补齐所有教学部分）
/lathe 面试 <slug> part-02          # 只处理指定部分
/lathe interview <slug>             # 英文关键词

# 也可从复习进入（等价写法）
/lathe 复习 <slug> 面试 [part-NN]

# 生成教程时同步产出
/lathe <主题> 面试
```

> `面试` / `interview` 必须是**独立 token**；作为首个 token 时**只有后跟一个已存在的 slug 才进入本模式**，否则按主题正常生成（如 `/lathe 面试题生成器怎么做`）。

### 只对教学部分产出

面试文档**只对教学部分**产出分段：

| 文件 | 是否产出分段 | 说明 |
|------|--------------|------|
| `part-01.md` 等**教学部分** | ✅ 唯一来源 | 承载「面试官可能问、且值得深挖」的教学要点 |
| `part-NN-review.md` **复习材料** | ❌ 不产出 | 回顾性内容，不含新要点 |
| 收尾**总结部分** | ❌ 不产出 | 全课程回顾 + 知识图谱，不含新要点 |

跳过复习材料与总结部分时**不提示、不报错**。

### 遗漏检测与补写确认

如果你在 `part-01` 时没开面试文档、到 `part-03` 才想写，技能会**先检测遗漏**再问你，不会静默漏掉前面的部分：

- **单 Part 触发**（`/lathe 面试 <slug> part-03`）或**续写建文档**时，给出二选一：

  ```
  该课程有 2 个教学部分尚无面试分段：Part 1、Part 2。
  你希望：
  1. ✅ 补写全部 —— 补齐 Part 1、2，并写入当前 Part 3（完善整个面试文档）
  2. ➕ 只写当前 —— 仅写入 Part 3，历史缺口保留
  请回复编号（默认 1）。
  ```

- **整课程触发**（`/lathe 面试 <slug>`）且文档**已存在但不完善**时，给出是/否确认：

  ```
  面试文档已存在（当前覆盖 Part 4–5），但尚缺 3 个教学部分：Part 1、2、3。
  按规则将补全这些部分（已有分段保持不动）。

  是否继续？[Y/n]
  ```

- 文档**不存在**或**已完善**时**不询问**——直接按规则生成，或报告「已是最新」。

> 判据：**只有「面试文档已存在、但覆盖不全」才需要确认。**

### 与续写的联动

**该教程已有面试文档时，续写会自动同步本部分的面试分段**（无需任何参数）：

- 续写完成后，为**刚写入的那个 Part** 追加一个分段，并更新文档头部的「本课程的进度」表；
- **已有分段一个字符都不动**；同号分段已存在时默认跳过，要求 `重写` 才覆盖；
- 续写时若面试文档**不存在** → 静默跳过，**不会**凭空创建文件；想同时创建就写 `/lathe 续写 <slug> 面试`；
- **收尾模式不产出面试分段**（总结部分不是教学部分）；
- 想跳过某次同步：`/lathe 续写 <slug> 不同步面试`（或 `--no-interview`）。

> ⚠️ **代价提示**：自动同步会给续写增加一次延伸研究（按 `topic_novelty` 取 3 / 5 / 8 次搜索预算）与一次写入。想保持轻快时用上面的逃生阀。

### 文档结构

```markdown
# <slug> · 面试要点

> **教程**：…  **教程目录**：…  **代码仓库**：…  **技术栈**：…  **状态**：…
> **所属阶段**：…（手填）  **对应计划**：…（手填）  **本阶段可投岗位**：…（手填）

**使用方法**：盖住答案，只看问题。能说出「结论 → 原理 → 取舍 → 我的项目」四层，才算掌握。

## 本课程的进度          ← 固定表，逐行更新

## 要点来源标注          ← 固定表（【课程】/【课程+延伸】/【延伸】）

---

# 第<中文数字>部分 · Part <阿拉伯数字>：<该 Part 一级标题>

## <N>-1 <问题> 【课程】
> **课程出处**：Part <N> ·《章节名》

**一句话回答**：…
<展开段：用主题化小标题，如「**原理**」「**四个理由**」>
**追问点**：…（可省略）
**我的项目里**：…（可省略）
```

**必写层只有两层**：`一句话回答` 与 `课程出处`；`追问点` 与 `我的项目里` **按内容取舍，没有就不写**。

**【延伸】类的末层固定为「尚未实践」**，禁止写成个人经验——面试官追问细节时，「我做过」和「我看过」是两种状态。

### 三条纪律

1. **不编造**：「我的项目里」只能是教程里真实出现过的文件/做法；无支撑时写「本阶段课程中的做法：……」，或整段省略。
2. **每条要点必须有课程出处**，便于回到课程回忆上下文。
3. **三态标注必须真实**：【课程】（直接讲过）/【课程+延伸】（提过但没展开）/【延伸】（按面试需要补写，**属于预习**）。

### 边界

- **面试文档不是 part**：不写入 `metadata.json` 的 `parts`、不命名为 `part-NN*.md`——因此 `/lathe 验证` 不会尝试执行它，`/lathe 列表` 与续写的编号推导也不受影响。
- 唯一写入：创建/追加面试文档、登记 `interview_paths`。**不修改任何教程文件**。

## /lathe 验证 — 验证教程

### 功能

在教程目录下的验证工作区（`.lathe-verify/`）中，像真实读者一样逐步执行教程，检查每步是否确实可用。工作区持久保留并增量复用——再次验证时不重新生成已有代码。

### 调用方式

```
/lathe 验证 <slug>
# 或使用英文关键词
/lathe verify <slug>
```

**示例：**

```
/lathe 验证 raft-go
/lathe verify raft-go
```

### 工作流程

1. **读取元数据** — 获取部分列表和所需工具
2. **版本一致性静态预检** — 不运行代码，先比对三类版本信息：`metadata.json` 锁定的工具链版本、配置代码块声明的版本（如 `Cargo.toml` 的 `edition`）、示例代码实际使用特性所需的最低版本。发现冲突（如 edition 2024 配 2021 语义的代码）直接进入修复流程，不等到运行才暴露
2b. **改动面静态预检** — 若 `metadata.changed_interfaces` 非空，只对本次待执行部分逐条核对调用点是否在教程中有代码块、插入位置或“无需改”说明；`runnable` 块中若仍出现旧签名，或调用点未覆盖，记为失败（改动面不完整）。**旧签名只对「变更引入之后」的部分检查**：待执行部分编号早于条目的 `part` 时，旧签名属历史正确状态，跳过不判失败。被增量复用跳过的部分继承上次结果。不做自动签名推断
2c. **代码块结构预检** — 每个 `fragment` 必须有文件/接缝说明，且同部分有覆盖最终状态的 `runnable` 或检查点；每个 `exercise` 必须有答案/检查方式。缺失则记为失败；只做结构检查，不执行片段/练习
3. **标记为进行中** — 写入 `verify-result.json`，状态设为 `verifying`
4. **准备验证工作区** — 位于教程目录下的 `.lathe-verify/`（首次验证时创建并在 `metadata.json` 中记录说明）。若用户要求全量、最后一个常规 part 编号是 3 的倍数、`changed_interfaces` 与上次 snapshot 不一致，或旧结果不可复用，则从 part-01 全量执行；否则**增量复用**：上次已通过且对应部分未修改的直接跳过，从第一个需要执行的部分（失败/未跑/内容已变更/新增）继续，依赖与编译缓存直接复用；针对仓库的教程（`repo` 非空）在工作区内克隆对应分支。**级联失效：** 从 `part-k` 重跑时，`part-k` 之后的常规 part 默认不可复用，顺序重跑；用户明确要求“只跑变更部分”时才跳过并标注风险
5. **逐步执行** — 按确定范围安装前置条件、创建文件、粘贴 `runnable` / `expected_failure` 代码块、运行检查点命令；`fragment` / `exercise` / `text` / `output` 跳过，不单独粘贴；`expected_failure` 校验预期非零退出/错误，意外成功记失败；`runnable` 块中出现 `...` 即视为代码不完整。报错时先归因——版本冲突类错误进入修复流程，其他错误按失败处理。**历史检查点：** 执行前汇总活跃 `changed_interfaces[].supersedes`；某部分的某组检查点（按正文 ①②③ 组号）被登记时跳过该组全部命令，在 `verify-result.json` 记 `historical_steps` 并注明「契约已变更」，**不算失败、不改失败横幅**；该部分其余步骤通过仍记 `passed`
6. **更新横幅并记录结果** — 先更新本次实际执行部分的验证状态横幅（通过→移除；失败/跳过→警告；未执行/复用跳过→不改；仅有历史检查点跳过→移除通过横幅，不写警告）。若只改了横幅、没有正文修复，刷新 `metadata.continuity.updated_at`，避免下次续写误判为手工编辑；若改了正文，保留旧时间让续写重建。再更新 `verify-result.json`（逐部分明细、`historical_steps`、`mode`、`changed_interfaces_snapshot`），并同步 `metadata.json` 的 `status`；工作区保留供下次增量验证使用

### 版本冲突检测与修复

这是验证环节重点强化的能力，专门解决"教程示例声明的版本与文本介绍的特性相冲突，读者照着敲代码才发现报错"这类问题：

1. **展示冲突详情**：所在部分、代码块位置、冲突的版本与特性，附证据（编译错误或官方文档链接）
2. **提出两个修复方向**并给出建议：
   - **方案 A**：改代码/文本对齐锁定版本（通常首选）
   - **方案 B**：调整版本声明并同步更新 `metadata.json` 的 `tools`
3. **你确认后才修改**，改动最小化（只动冲突相关内容，不改 voice 和结构）；拒绝修复则保留原文按失败记录
4. **修复后重新执行该部分**，确认真正生效；修复内容记入 `verify-result.json` 对应部分的 `fixes` 数组

### 安全护栏

- 所有命令只在验证工作区（`.lathe-verify/`）内执行，不碰你的项目和全局环境
- 需要 `sudo`、全局安装、工作区外删除等敏感操作时会先向你确认，未确认则记为 `skipped`
- 长时间运行的命令后台执行并验证后终止，单命令约 5 分钟无进展视为异常
- 验证结束后工作区**静默保留**（不会询问是否清理）；它是隐藏目录，可以安全手动删除——下次验证会自动重建并全量执行

### 验证结果

验证完成后会产生三种状态之一，并附逐部分明细（`passed` / `failed` / `not_run`）：

| 状态         | 含义   | 场景                   |
| ---------- | ---- | -------------------- |
| `verified` | 验证通过 | 所有检查点输出与教程声明一致（含经版本冲突修复后通过，修复记录在 `fixes`） |
| `skipped`  | 跳过   | 缺少必需工具，或敏感操作未获确认 |
| `failed`   | 验证失败 | 代码无法编译、输出不匹配、步骤矛盾（非版本冲突类，或你拒绝了修复） |

验证通过后 `metadata.json` 的 `status` 会同步更新为 `verified`。

### 注意事项

- 验证对教程部分**默认只读**；唯一例外是版本冲突修复，且必须先获你确认、改动最小化
- `skipped` 不等于 `failed`——缺少工具是环境问题，不是教程问题
- 验证前需要本地安装教程所需的工具链

## /lathe 提问 — 提问教程内容

### 功能

针对教程的特定部分提出问题，AI 会基于该教程的具体内容回答，而非泛泛地重新讲解主题。

### 调用方式

```
/lathe 提问 <slug> [part] <你的问题>

# 或使用英文关键词
/lathe ask <slug> [part] <your question>
```

**part 参数宽松匹配：** `part-01.md`、`part-01`、`1` 均可；也可以**直接省略**，AI 会根据问题内容自动定位最相关的部分，无法判断时列出部分列表让你选择。

**示例：**

```
/lathe 提问 raft-go part-01
为什么用环形缓冲区而不是 channel？

/lathe ask raft-go 1
为什么用环形缓冲区而不是 channel？

/lathe 提问 digital-synth-zig
如果滤波器截止频率超过奈奎斯特频率会怎样？（省略 part，自动定位）
```

### 回答原则

- **扎根于本教程** — 使用教程中相同的示例、数字和术语回答
- **指向具体位置** — 优先"看 §3 中的 `process_buffer` 循环"而非从头推导
- **对缺口诚实** — 如果问题暴露了教程的错误或含糊之处，会直接说明
- **对话式** — 保持会话以回答后续追问

### 发现错误时的勘误确认

如果 AI 核对后确认教程**确实有错**（事实与官方来源不符、代码按步骤跑不通、数字前后矛盾、缺运行必需步骤），它会先回答你的问题，再在末尾给出一个勘误确认块：位置、问题、依据、原文、修正、影响。**只提议，不写文件**，你需要手动选择：

| 回复 | 结果 |
|---|---|
| `1` 或「确认修改」 | 原地修正那一处片段；该部分横幅换回「未验证」，`verified` 改回 `unverified`；记入 `research.md` 的 `## Errata`；建议重新验证 |
| `2` 或「只记勘误」 | 正文不动（适合已经在学、想冻结的课程），只记入 `## Errata`；下一次续写会在 RECALL 或相关章节用一句话更正 |
| `3` | 不处理 |

只回复「好」「嗯」「可以」不算确认，AI 不会动文件。措辞偏好或想补充新知识点不算勘误，请用 `/lathe 续写 <slug> <指导>`。

## /lathe 标签 — 管理教程标签

### 功能

为教程选择或更新搜索标签，使教程更容易被发现和分类。

### 调用方式

```
/lathe 标签 <slug>
# 或使用英文关键词
/lathe tag <slug>
```

**示例：**

```
/lathe 标签 raft-go
/lathe tag raft-go
```

### 标签规范

AI 会选择 2-5 个小写、可复用的标签，涵盖以下维度：

| 维度         | 示例                                           |
| ---------- | -------------------------------------------- |
| **语言/运行时** | `go`、`rust`、`zig`、`python`                   |
| **领域**     | `compilers`、`databases`、`audio`、`networking` |
| **核心技术**   | `consensus`、`dsp`、`parsing`、`concurrency`    |

优先选择能与其他教程自然分组的通用标签，避免过于具体的一次性标签。

### 操作方式

- **设置标签：** 完全替换 `tags` 数组
- **添加标签：** 追加到现有数组并去重
- **移除标签：** 从现有数组中删除

标签保存在 `metadata.json` 的 `tags` 字段中。

## /lathe 语气 — 创建自定义语气

### 功能

创建自定义的写作语气（Voice）预设，控制教程的文风、视角和表达方式。

### 内置 Voice

| Voice               | 特点                    | 适用场景          |
| ------------------- | --------------------- | ------------- |
| **plainspoken**（默认） | 直接、精确、不虚构人格。平实散文，信任读者 | 大多数技术教程       |
| **companion**       | 温暖、幽默、第一人称。键盘旁的老朋友    | 入门教程、需要亲和力的场景 |
| **craftsman**       | 从容的匠人师傅。散文式构建，长短句交替，类比贯穿，先讲"为什么"再讲"怎么做" | 需要深度讲解设计决策的教程 |

### 调用方式

```
/lathe 语气 [名称]
# 或使用英文关键词
/lathe voice [name]
```

**示例：**

```
/lathe 语气 terse
/lathe voice terse
/lathe 语气 field-notes
/lathe voice field-notes
```

### 创建流程

1. **选择名称** — 提供或确认一个简短的 slug（如 `terse`、`socratic`）
2. **风格访谈** — AI 会询问：
   - 正式 ↔ 随意？密集 ↔ 疏朗？冷峻 ↔ 温暖？
   - 人称：第一人称、协作式还是非人称？
   - 幽默程度：无、克制还是活泼？
   - 这种 voice 绝不应该像什么？
3. **起草规范** — 生成包含三个章节的 markdown 文件：风格与调性、避免、校准对比
4. **展示并确认** — 展示完整草稿，迭代直到你批准
5. **持久化** — 写入 `<TUTORIALS_DIR>/voices/<名称>.md`

### 使用自定义 Voice

创建后，在生成教程时指定 voice：

```
/lathe 用 Rust 构建解析器，使用 terse voice
```

Voice 名称会记录在 `metadata.json` 中，`/lathe 续写` 会自动继承。

### 管理 Voice

- **查看已有 voice：** 检查 `<TUTORIALS_DIR>/voices/` 目录
- **删除 voice：** 直接删除对应的 `.md` 文件
- **内置 voice 不可覆盖：** `plainspoken`、`companion` 和 `craftsman` 保留为内置

### 安全护栏

技能会拒绝创建以下 voice：

- 冒充真实人物的 voice
- 虚构资历或权威背书的 voice
- 试图将 AI 生成内容伪装为人类撰写的 voice

## /lathe 扫描 — 扫描登记教程

### 功能

把**存在于磁盘但不在 `~/.lathe/config.json` 视野内**的教程登记进来，并清理指向已消失目录的失效条目。

### 什么时候需要它

生成新教程时会自动登记位置，但教程也会通过其他途径出现——而配置里的“已使用过”扫描分支**只在配置文件不存在时触发**，所以配置一旦建立，这些教程就永久不可见：

| 场景 | 现象 |
|------|------|
| 从他人仓库 `git clone` 拉下教程 | `/lathe 列表` 看不到它们 |
| 手工拷贝或移动了教程目录 | `/lathe 续写 <slug>` 提示“未知 slug” |
| 跳机器同步（新电脑上只有教程没有配置） | 所有教程都不可见 |
| 删除了某个教程目录 | 配置里留下指向不存在路径的悬空条目 |

本操作是这些情况的**唯一修复入口**。

### 调用方式

```
/lathe 扫描                    # 扫描已知目录（默认目录 + 已登记的各位置）
/lathe scan                   # 同上（英文关键词）
/lathe 扫描 ~/projects/tutorials ~/Downloads/lathe   # 扫描指定目录
```

中文关键词 `扫描`、`登记`、`注册` 与英文 `scan`、`register`、`sync` 等价。

### 扫描报告

AI 会一次性展示全部结果（不逐条询问），经你确认后才写入配置：

```
扫描了 2 个目录，发现：

🆕 待登记（3）
- todo-cli-rust — 用 Rust 构建命令行待办事项应用（5 个部分）｜~/projects/tutorials
- raft-go — 用 Go 实现 Raft（2 个部分）｜~/projects/tutorials
- wasm-jit ⚠️ metadata 缺失，发现 3 个 part 文件｜~/others/lathe_tutorials

🔀 待更正路径（1）
- taskr：config 记录 ~/others/lathe_tutorials，实际在 ~/projects/tutorials

🗑️ 悬空条目（1）
- old-experiment：config 指向的目录已不存在

要应用这些变更吗？（可以只应用部分——告诉我跳过哪些）
```

| 分类 | 含义 | 处理 |
|------|------|------|
| 🆕 待登记 | 磁盘上有但 config 里没有 | 写入 `tutorial_paths` |
| 🔀 待更正路径 | 已登记但实际位置变了 | 更新为实际位置 |
| 🗑️ 悬空条目 | config 指向的目录已不存在 | 从 config 中移除映射（**不删任何磁盘内容**） |
| ⚠️ 副本冲突 | 同一 slug 在多个目录下都存在 | **必须由你指定**保留哪个作为登记位置 |
| ✅ 已是最新 | 已登记且路径一致 | 不动 |

### 边界

- **唯一写入的文件是 `~/.lathe/config.json`。** 不创建、不修改、不删除任何教程文件或 `metadata.json`
- **不重建 metadata**——只识别并报告缺失；重建由你后续对该教程执行写入型操作（如 `/lathe 标签 <slug>`）时按自愈协议完成
- **“清理悬空条目”仅指移除 config 里的失效映射**，教程目录本身若存在就绝不触碰
- 未经你确认不写入 config

## /lathe 列表 — 列出教程

### 功能

列出所有已存储的教程，或查看单个教程的详细状态。忘记 slug、想了解整体学习进度时非常有用。完全只读，不修改任何文件。

### 调用方式

```
/lathe 列表          # 列出所有教程
/lathe list          # 同上（英文关键词）
/lathe 列表 raft-go  # 查看单个教程详情
/lathe list raft-go
```

### 展示方式

**按编程语言分组：** 如果你同时学习多门语言（如 Rust 和 Zig），教程会按语言分大类展示；只有一门语言时不分组。语言从 `tags` 中的语言标签识别，缺失时从工具链/主题推断。

**多路径枚举：** 列表会枚举配置中登记的所有目录（`tutorial_paths` 各值 + 默认目录），保存在不同位置的教程都能被找到；非默认目录下的教程会额外标注所在路径。若发现某目录有 `part-*.md` 但缺 `metadata.json`，会单独标注 *⚠️ metadata 缺失* 并提示可自愈重建。

> 💡 **成本约束：列表绝不读取 `part-NN.md` 的全文。** 它只需要每个部分的一级标题，所以优先用 `metadata.json` 的 `continuity.part_titles` 映射（零文件读取），映射缺失时用 `grep` 只取标题行。否则一个多课程目录的正文动辄数十万字符。

**内容变更检测：** 若某 part 在 `verify-result.json` 中为 `passed`，但该 part 文件的修改时间晚于 `checked_at`，列表会标记 **“内容已变更，需重新验证”**，不再显示 `passed`。只取文件 mtime，不读正文；`-review` 复习材料不参与。逐部分状态还会显示 `passed` / `failed` / `skipped` / `not_run`。若 `changed_interfaces_snapshot` 与当前 `metadata.changed_interfaces` 不一致，也会标记 **“接口已变更，需重新验证”**。

**异常提示（只提示，不写入）：**

- **验证中断检测** — `verify-result.json` 停留在 `verifying` 且超过 6 小时，标注为 *⚠️ 验证可能中断* 并提示重新运行 `/lathe 验证 <slug>` 即可复位（增量复用会从断点继续）；
- **悬空与未登记** — `tutorial_paths` 有条目指向不存在的目录，或发现了尚未登记的教程时，会各用一句话告知并建议运行 [`/lathe 扫描`](#lathe-扫描--扫描登记教程)。**尤其当你发现“有教程没显示出来”时，首选 `/lathe 扫描`**——列表是只读操作，无权修复登记。

**课程逐部分展示：** 每门课程展示全部部分及各部分标题，并标注验证结果：

```

**todo-cli-rust** — 用 Rust 构建命令行待办事项应用

1. part-01.md — 搭建项目骨架与基础命令 ✅ passed
2. part-02.md — 添加优先级与标签 ✅ passed
3. part-03.md — 模块化重构与集成测试 ✅ passed

### Zig

**digital-synth-zig** — 用 Zig 构建数字合成器
状态：unverified ｜ 最近验证：— ｜ 标签：zig, audio, dsp ｜ 正文语言：zh-CN
积压：2 条（core 2）
```

> **积压行**只在 `knowledge_backlog` 非空时显示（`n` = 总条数，`m` = 其中 `priority: core` 的条数），只读 metadata、不读正文；为空时整行省略，不显示「积压：0 条」。单教程详情（`/lathe 列表 <slug>`）另外显示一行**知识点账本**统计：`账本：taught a · queued b · planned c · self-study d · dropped e · duplicate f（共 n 条）`；账本与积压对不上时会提示。

**单教程详情：** 展示标题、主题、编程语言、正文语言、voice、部分列表（含逐部分验证结果）、锁定工具版本、验证结果等，并根据状态给出下一步建议（如未验证 → 提示可验证）。字段存在时还会展示学习目标（`goal`）、读者水平（`experience_level`）、风格锚点（`style_anchor`）、生成版本（`lathe_version`）、**积压条数与自学清单条数**，以及 `continuity` 摘要的新鲜度（落后时提醒：下次续写会先重建摘要，属一次性成本）。积压非空时，续写建议会优先说明「先还债」。

```json
    "note": "📦 教程验证工作区：/lathe 验证 在此目录中执行教程代码，并在再次验证时增量复用。可以安全删除，下次验证会自动重建。"
  }
}
```

### continuity 连续性摘要

`continuity` 存在的唯一目的：让续写**不必重读全部历史部分**。教程越长收益越大。

| 字段 | 含义 |
|------|------|
| `controlling_example` | 贯穿全课程的具体产物。续写必须精确复用，不得替换 |
| `fixed_numbers` | 已锁定的领域数字（采样率、超时、缓冲区大小等）。续写引用同一数字，不得漂移 |
| `metaphor` / `metaphor_retired` | 控制性隐喻及是否已明确告别。已告别则不再重启 |
| `covered_concepts` | 已讲透的概念清单——避免重复教学，也是 `[!RECALL]` 的取材池。**只追加、不合并**，每项 ≤40 字 |
| `open_threads` | 已提出但尚未展开的问题/伏笔（最多 10 条，每条 ≤80 字）。续写优先回收；已解决/溢出移到 `research.md` 的 `## Open Threads Archive`，不删除 |
| `next_hook` | 最后一部分“接下来”指向的方向——下次续写的默认任务（≤200 字） |
| `part_titles` | 文件名 → 一级标题映射。让列表、复习、收尾无需打开文件即可获得标题 |
| `updated_through` | 摘要覆盖到哪个部分——**新鲜度判定依据** |
| `updated_at` | 最后一次写回 continuity 的时间；也用于 part mtime 的手工编辑检测，必须在所有 part 写入之后刷新 |

**新鲜度规则：** `updated_through` 等于当前最后一个常规部分 → 摘要可信，续写只读它 + 最后一个部分；落后或缺失 → 全文读取一次并重建。**信任前先用文件 mtime 检查手工编辑：任何 part 的 mtime 晚于 `continuity.updated_at`，按重建处理；每 3 个常规部分（part-03/06/09…）做一次全读审计。** 摘要总量控制在 **1200 字软上限 / 2000 字硬上限**；分字段上限：`controlling_example` ≤200 字、`next_hook` ≤200 字、`covered_concepts` 每项 ≤40 字、`fixed_numbers` 每个值 ≤40 字、`open_threads` 每条 ≤80 字。**宁可多存 200 字，也不要让下次续写重读全部部分。** 它是索引，不是缩写版教程；**这是索引预算，不是正文预算**，超出时归档/压缩索引字段，不压缩课程正文。

`open_threads` 超过 10 条或已解决时，移到教程目录下可选 `research.md` 的 `## Open Threads Archive`；归档内容写清问题、提出部分、状态、解决部分（如有）、备注/来源。归档不是删除。

> 手工修改过旧部分内容后，可以直接把 `continuity.updated_through` 改成一个较小的值（或删掉整个 `continuity` 字段），下次续写就会重新全文读取并重建摘要。也可以直接告知 AI “我改过前面的部分”。

### changed_interfaces 与 research.md

`changed_interfaces` 是跨部分活跃接口变更清单，用来防止“某个部分改了签名，后续部分还按旧签名写”。它在 `metadata.json` 顶层，不占 `continuity` 的 1200/2000 索引预算。

```json
{
  "changed_interfaces": [
    {
      "file": "src/documents/documents.service.ts",
      "symbol": "DocumentsService.findAll",
      "from": "findAll(limit: number)",
      "to": "findAll(query: QueryDocumentsDto)",
      "call_sites": ["src/documents/documents.controller.ts"],
      "part": "part-02.md"
    }
  ]
}
```

- 按符号记录，最多 8 条；`call_sites` 为空表示已确认无需外部改动，并在 part 的改动面表说明理由。
- 同一符号只保留最新一条活跃条目；旧条目、超出 8 条的条目移到 `research.md` 的 `## Changed Interfaces Archive`；仍有活跃溢出时标记 `active (overflow)`，续写/验证涉及该符号时读取归档。
- 续写前先读活跃条目；本部分涉及归档接口时读 `research.md` 对应小节；验证把清单当检查表，不做自动签名推断。
- 旧教程缺失视为空数组，不强行回填。

`research.md` 是可选归档文件，只在需要时创建，最多五个固定小节（按此顺序、没内容的不写）：`## Changed Interfaces Archive`、`## Open Threads Archive`、`## Covered Concepts Archive`（从 `covered_concepts` 移出的旧概念，**仍算已讲**）、`## Self-study Backlog`（你显式选择降级的条目，**保留原 ID**）、`## Errata`（提问勘误的记录）。`knowledge_backlog` 的条目 `priority` 固定为 `core`；自学条目只在 `research.md`，两边不重复。

### syllabus.json（知识点账本）

与 `metadata.json` 并列，课程承诺讲的每个知识点一条记录，**状态改变时改字段、永不删除条目**。它回答「我要的 3b 讲在哪一节」「哪些还没讲、为什么」「有没有点既没讲也不在任何队列里」。

```json
{
  "_warning": "⚠️ 本文件是该教程的知识点账本，请勿删除或手工删条目。…",
  "slug": "nest-kb-service",
  "updated_at": "2026-10-24T00:00:00Z",
  "points": [
    {"id": "3b", "text": "JWT payload 放什么", "original": "鉴权", "parent": "3", "src": "user",
     "from": "user-list-2026-10-24", "tag": "main", "plan_ref": 3, "status": "taught",
     "at": "part-04.md#JWT payload 放什么", "depth": "full", "dup_of": null, "note": ""}
  ]
}
```

| 状态 | 含义 |
|---|---|
| `planned` | 已列入大纲，按路线图在后续 Part 讲 |
| `queued` | 名额不够被挤出、欠着的债（与 `knowledge_backlog` 一一对应） |
| `taught` | 已讲；`at` 记下讲在哪个 part 的哪一章，`depth` 记下讲法（构建章 / 地基 / §0 承接 / 档 1 融入） |
| `self-study` | 你**显式**选择降级；同 ID 记在 `research.md` 的 `## Self-study Backlog` |
| `dropped_by_user` | 你**显式**删除（写前确认里删掉、闸门选 ③），`note` 记下时间与原因 |
| `duplicate` | 与已有条目或已讲概念语义完全相同，`dup_of` 记下对应哪一条 |

**书写格式**：每个知识点一行一个对象，空的可选字段（`original` / `parent` / `at` / `depth` / `dup_of` / `note`）整个省略——续写时可以只取未结条目（`grep '"status": "queued"'`），也能按行改写某一条。**ID 镜像**：`metadata.json` 的 `syllabus_ids` 按字母序记下账本里出现过的全部 ID，只增不删；任何操作发现镜像里有、账本里没有的 ID，会停下来报告「这些条目被删了」并请你确认恢复，`/lathe 列表 <slug>` 也会提示。

`id` 规则：你给的清单保留原文编号（如 `3a`，冲突时加 `L<NN>-` 前缀）；大纲派生的写 `P<plan>-<k>`；必做练习引入的新概念写 `E<part>-<k>`；去重产生的深化条目写 `<原 id>-d`。`self-study` 与 `dropped_by_user` 只能来自你的选择，AI 不会自行设置。旧教程第一次续写时会按正文回填账本（推断条目标 `inferred`），先给你确认，不改任何旧部分。完整字段、不变量与读写规则见技能包 `references/knowledge-ledger.md`。

### 检查脚本（`skills/lathe/scripts/`）

技能自带三个纯标准库 Python 3 脚本，写作型操作有 shell 时会自动调用，你也可以手动跑：

```bash
python3 <技能目录>/scripts/part_lint.py    <教程目录>/part-03.md          # 结构、契约四行、代码块类型、练习上限、实写章数
python3 <技能目录>/scripts/trial_run.py    <教程目录>/part-03.md --run    # 在临时目录逐块编译/运行 runnable 与 expected_failure
```

`trial_run.py` 支持 Rust（rustc）、Python、JavaScript（node）的单文件块；依赖前文代码或外部依赖的块标为「需拼工程」，shell 命令块只做语法检查、从不执行。它不是 `/lathe 验证`：不写 `verify-result.json`、不改横幅与 `status`。

### 代码块类型

代码块 fence 的 info string 可带类型标记（类型词紧跟语言名，如 `rust runnable`；之后可附 `file=...` 等属性，接缝仍以前文说明为准）；未标记按 `runnable` 处理，`mermaid` / `plantuml` / `dot` 图表块例外，未标记也视同 `text`、不占步骤号：

| 标记 | 用途 | 验证行为 |
|------|------|----------|
| `runnable` | 完整可运行/可编译的单元 | 执行 |
| `fragment` | 片段；前文写明所属文件与接缝 | 跳过，不单独执行 |
| `exercise` | 练习/填空；应有参考答案或检查方式 | 跳过，不执行 |
| `text` / `output` | 非执行文本：预期输出、文法、文件树、日志、树形 | 跳过，不占步骤号 |
| `expected_failure` | 故意失败的命令；前文写明预期退出码/错误 | 执行并期望非零退出；意外成功记失败 |

同一文件的完整代码如果拆成多个 `fragment`，教程要另外提供覆盖最终状态的 `runnable` 块或检查点。`runnable` 块中不要出现 `...`；无关样板请放在 `fragment` 块，`runnable` 块中出现 `...` 视为代码不完整。单个 `runnable` 超过约 100–120 行时，优先按文件/逻辑段拆成多个完整块；测试单独成块。

> 旧教程没有标记：未标记块按 `runnable` 处理；如果旧教程中的片段/`...` 被验证误判，给该块补 `fragment` / `exercise` 标记即可，不需要改正文。**旧教程无需强制迁移**；建议先备份，盘点 `...`/填空/片段，补代码块类型和 metadata 缺失字段，再运行一次全量验证。

### 验证状态横幅

每个 part 的 H1 之后、正文之前可以有一个验证状态横幅，由生成/续写/验证维护。固定标记如下：

```markdown
<!-- lathe:verify-status:start -->
> [!WARNING]
> 本部分尚未通过端到端验证。生成于 <YYYY-MM-DD>；运行 `/lathe 验证 <slug>` 查看结果。
<!-- lathe:verify-status:end -->
```

- 生成/续写写入“未验证”警告；验证失败写 WARNING（含失败步骤），部分跳过写 NOTE（含原因）；通过后移除整个块，**不写“已验证”正面横幅**。全局 `skipped` 且没有逐部分结果时不改横幅，保留未验证警告。
- 旧 part 没有横幅：验证失败/跳过时可以插入；通过时不添加。
- 增量复用跳过的部分不改横幅。
- 验证必须**先更新横幅，再写 `verify-result.json` 的 `checked_at`**，否则 part 的 mtime 会晚于 checked_at，下次会被误判为“内容已变更”。
- 横幅不是教程正文，不计入结构或知识点配额。

### verify-result.json

验证结果文件，记录整体状态和逐部分明细；经版本冲突修复后通过的部分会附 `fixes` 记录。逐部分状态可以是 `passed` / `failed` / `skipped` / `not_run` / `not_applicable`；全局 `skipped` 且没有 `parts` 时，保留原有横幅。结果还记录 `mode`（`full` / `incremental`）和 `changed_interfaces_snapshot`（当前活跃接口清单的 JSON 副本，空也写 `[]`）；下面的示例为简洁省略了这两个字段：

```json
{
  "status": "verified",
  "checked_at": "2025-01-15T10:30:00Z",
  "parts": [
    {"part": "part-01.md", "status": "passed"},
    {"part": "part-02.md", "status": "passed", "fixes": ["Cargo.toml 锁定 edition 2024，但测试代码按 2021 语义编写；已改写为 edition 2024 写法"]}
  ]
}
```

失败时 `parts` 中对应部分会包含 `failed_step`（部分内 `runnable` / `expected_failure` 代码块与检查点命令的顺序编号；`fragment` / `exercise` / `text` / `output` 不占步骤号）和 `error` 字段，未执行的部分记为 `not_run`。

### 面试文档（interview.md / `<slug>.md`）

面试文档**不在教程目录里也可以**（位置见[面试文档的存储位置](#面试文档的存储位置)），且**不是**教程的 `part`——它不计入 `parts`、不参与验证。默认落在教程目录内时命名为 `interview.md`，落到外部目录时命名为 `<slug>.md`。

```markdown

## 要点来源标注          ← 固定表（【课程】/【课程+延伸】/【延伸】）

# 第一部分 · Part 1：<该部分一级标题>

> **课程文件**：`…/part-01.md`（657 行）
> **本部分覆盖的章节**：《…》→《…》

## 1-1 <问题> 【课程】
> **课程出处**：Part 1 ·《章节名》

**一句话回答**：…
（展开段：主题化小标题）
**追问点**：…（可省略）
**我的项目里**：…（可省略）

# 第二部分 · Part 2：…
```

要点编号为 `<Part 序号>-<该部分内序号>`；**必写层只有「一句话回答」与「课程出处」**。

### 标注类型速查

| 标注                 | 用途              | 使用频率       |
| ------------------ | --------------- | ---------- |
| `> [!PREDICT]`     | 检查点前的预测提示       | 每个检查点 1 次；每部分 1-3 次 |
| `> [!RECALL]`      | 第 N≥2 部分顶部的间隔检索 | part-01 为 0；part-02 起顶部 1 次；按主要知识点边界可增加，不以字数为触发 |
| `> [!HEADS-UP]`    | 即将踩坑的警告         | 每个真实陷阱 1 次；不设总数上限 |
| `> [!ASIDE]`       | 词源、故事等旁白        | 装饰性；每部分 ≤2 次；保持简短 |
| `> [!DESIGN-NOTE]` | 多段落的"为什么"讨论     | 每个独立设计决策 1 次；放章节末尾；不设每章 1 个的硬上限 |
| `> [!UNVERIFIED]`  | 无法确认的关键声明       | 按需；≥3 个关键事实时先补研究 |
| `> [!NOTE]`        | 中性补充信息          | 按需；不设总数上限；每个对应具体知识点/真实陷阱 |
| `> [!TIP]`         | 便捷技巧            | 按需；不设总数上限；每个对应具体知识点/真实陷阱 |

> 信息型标注（HEADS-UP、NOTE、TIP）不设总数上限，也不设每章节硬上限；每个标注必须对应一个具体知识点或真实陷阱。ASIDE 每部分 ≤2 个，纯装饰。标注是强调手段，但不得用总数上限删掉教学警告、必要补充、类比或边界说明。

## 常见问题

### Q：教程可以跨多个会话续写吗？

可以。每次调用 `/lathe 续写`（或 `/lathe extend`）时，AI 会从 `metadata.json` 和已有部分文件中读取完整上下文，因此即使换了会话甚至换了 AI 模型，也能无缝续写。

### Q：可以在不同的 AI 工具之间切换使用吗？

技能采用标准的 Agent Skills 布局（`SKILL.md` 入口 + `references/` 子目录），这是 Anthropic 提出的开放规范，多个 AI 工具均已支持：

| 客户端 | 用户级目录 | 项目级目录 | 状态 |
| --- | --- | --- | --- |
| QoderWork / QoderWork CN | `~/.qoderwork/skills/` | `.qoderwork/skills/` | ✅ 已测试 |
| Reasonix（DeepSeek 原生终端 Agent） | `~/.reasonix/skills/` | `.reasonix/skills/` 或 `.claude/skills/` | ✅ 机制已验证（原生支持 SKILL.md 标准，自动注入 references/ 内容，配合 DeepSeek V4 使用） |

在未列出的其他工具（如 Qoder、Qwen Code 等）中可能无法正常工作，使用前建议先小规模验证。

> **提示：** 教程数据由 `~/.lathe/config.json` 管理（默认目录 `~/others/lathe_tutorials/`，也支持多路径存储），与具体客户端无关——在 QoderWork 和 Reasonix 之间切换时，教程、标签、验证结果完全共享。

### Q：验证失败了怎么办？

查看 `verify-result.json` 中 `parts` 数组里失败部分的 `failed_step` 和 `error` 字段定位问题。常见原因：

- 代码块中的代码不完整或有遗漏
- 检查点命令的预期输出与实际不符
- 前置条件遗漏了某个工具

注意：**版本冲突类问题（如示例声明的版本与代码使用的特性不匹配）不会直接记为失败**——验证时会自动检测并在你确认后修复，修复记录在 `fixes` 字段。其他问题修复教程后重新运行 `/lathe 验证`（或 `/lathe verify`）。

### Q：如何修改已生成教程的内容？

直接在编辑器中修改 `part-NN.md` 文件即可。修改后建议重新运行 `/lathe 验证`（或 `/lathe verify`）确认可用性。

### Q：Voice 会影响教程的准确性吗？

不会。Voice 仅控制语气和风格（如是否使用第一人称、幽默程度等）。教程的准确性、研究纪律、引用规范和验证规则是不变量，不受 Voice 影响。

### Q：如何查看所有已生成的教程？

直接使用 `/lathe 列表`（或 `/lathe list`），教程会按编程语言分组展示，每门课程逐部分列出并附验证状态。也可以直接浏览教程基础目录（默认为 `~/others/lathe_tutorials/`），或通过标签筛选：

```bash
# 查找包含特定标签的教程
grep -rl '"compilers"' ~/others/lathe_tutorials/*/metadata.json
```

### Q：教程分散在多个目录，还能统一管理吗？

可以。分两种情况：

- **配置文件丢失（首次重建）：** 调用 `/lathe` 时回答"已经使用过"并提供所有教程位置，技能会扫描验证并逐个登记到 `tutorial_paths`。
- **配置已存在，但新增了未登记的教程**（手工拷贝、`git clone`、目录移动、跨机器同步）：用 [`/lathe 扫描`](#lathe-扫描--扫描登记教程) 把它们登记进来，并顺带清理已失效的条目——这是配置建立之后发现教程的唯一入口。

之后生成新教程时也可随时指定不同的保存位置。`/lathe 列表` 会扫描所有已登记目录，非默认目录下的教程会标注所在路径。

### Q：误删了某个教程的 metadata.json 怎么办？

运行 `/lathe 列表` 会看到该教程被标注为 *⚠️ metadata 缺失*。随后对它执行任一写入型操作（如 `/lathe 标签 <slug>` 或 `/lathe 续写 <slug>`），技能会自动检测到缺失，从 `part-*.md` 正文推断各字段（标题、语言、工具版本、来源等），展示推断结果经你确认后重建索引——教程正文本身不会被动到。

### Q：面试文档和复习材料有什么区别？

- **复习材料**（`part-NN-review.md`）是**课程内的回顾**——逐部分回顾、自测题、重跑检查点，计入 `parts`，会被 `/lathe 列表` 标注 *（复习）*。
- **面试文档**（`<slug>.md` 或 `interview.md`）是**课程外的独立文件**——一个 slug 一个文档，按 Part 分章，每条要点给出「一句话回答 → 展开 → 追问点 → 我的项目里」的面试表达，**不计入 `parts`**、不参与验证，`/lathe 列表` 也不会把它当成教程部分。

两者可以同时存在，互不干扰。

### Q：面试文档会漏掉早期的部分吗？

不会。技能在**任何面试写入之前**都会先算一次遗漏集合（教学部分中尚无分段的那些）：

- **单 Part 触发**（如 `/lathe 面试 raft-go part-03`）或**续写建文档**时，会先问你**补写全部**还是**只写当前**（默认补写全部）；
- **整课程触发**且文档**已存在但不完善**时，会先给出待补清单并要你确认；
- 文档**不存在**或**已完善**时**不打扰**。

另外，**该教程已有面试文档时，续写会自动同步本部分**——不必每次手动补。

### Q：面试文档为什么不为复习材料生成分段？

因为复习材料（`part-NN-review.md`）是**回顾性内容**——它本身就是对已有部分的重新组织（逐部分回顾、自测题、重跑检查点），**不含新的教学要点**。为它建分段只会产生重复条目。同理，收尾的**总结部分**也不产出分段（它是全课程回顾 + 知识图谱 + 目标对照）。跳过这两类文件时**不提示、不报错**。

### Q：意图不明确时会发生什么？

当你只输入 `/lathe` 或输入含糊的内容时，AI 不会默认生成教程，而是展示一个操作选项菜单（生成 / 续写 extend / 验证 verify / 提问 ask / 标签 tag / 语气 voice / 扫描 scan / 列表 list / 面试 interview），让你选择想要执行的操作（复习 review 通过关键词显式触发）。
