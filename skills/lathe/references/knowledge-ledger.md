# 知识点账本（单一事实源）

本文件集中了「本部分讲哪些知识点、没讲的去了哪、怎么向用户交代」的全部规则。**生成、续写、收尾读取本文件**；复习、列表只读 `syllabus.json` 的数据，不需要本文件。其他文件只引用这里，不再复述。

`<SKILL_DIR>/scripts/` 下的三个脚本把这里能机械检查的部分做成了代码（纯标准库 Python 3）。**有 shell 时以脚本输出为准，回执里的数字直接粘贴脚本输出；没有 shell 时按本文逐条人工核对。**

| 脚本 | 做什么 | 何时跑 |
|---|---|---|
| `ledger_check.py <教程目录> [--receipt part-NN.md]` | 账本不变量、ID 镜像、`queued`=积压、`at` 命中章节、档 3 提醒带 ID；`--receipt` 打印「本部分覆盖」行与账本统计 | 生成/续写/收尾写回之后；续写读账本之前（只核 ID 镜像时也可跑） |
| `part_lint.py <part 文件>` | 结构、契约四行、续写变体、代码块类型、练习上限；打印「实写 N 章」 | 每写完一个 part，落盘之前 |
| `trial_run.py <part 文件> --run` | 交付前试跑（见 writing-core.md），打印「试跑：…」行 | 每写完一个 part，落盘之前 |

退出码非 0 就先修再交付；脚本报的问题不得在回执里略过。

## 1. 账本 `syllabus.json`

放在教程目录、与 `metadata.json` 并列。**课程承诺讲的每个知识点一条记录，状态改变时改字段，永不删除条目。** 它回答：「我要的 3b 讲在哪一节」「哪些还没讲、为什么」「有没有点既没讲也不在任何队列里」。单独成文件是为了不占 `continuity` 预算、`metadata.json` 损坏时账本仍在。

### 结构与书写格式

```json
{
  "_warning": "⚠️ 本文件是该教程的知识点账本，请勿删除或手工删条目。lathe 用它核对每个知识点是否讲到；误删后下一次续写会按正文推断重建（推断条目会标 inferred）。",
  "slug": "<slug>",
  "updated_at": "<ISO 8601 时间戳>",
  "points": [
    {"id": "3b", "text": "JWT payload 放什么", "original": "鉴权", "parent": "3", "src": "user", "from": "user-list-2026-10-24", "tag": "main", "plan_ref": 3, "status": "taught", "at": "part-04.md#JWT payload 放什么", "depth": "full"},
    {"id": "P5-2", "text": "刷新令牌的轮换", "src": "plan", "from": "course_plan#5", "tag": "main", "plan_ref": 5, "status": "planned"}
  ]
}
```

**一行一个知识点**，不缩进展开。必填字段（`id`、`text`、`src`、`from`、`tag`、`plan_ref`、`status`）始终写出，`plan_ref` 无归属写 `null`；可选字段（`original`、`parent`、`at`、`depth`、`dup_of`、`note`）为空时**整个省略**。这样每条约 320 字节，有 shell 时可以 `grep` 只取未结条目，也能按行改写某一条。

| 字段 | 说明 |
|---|---|
| `id` | 全课程唯一。用户清单保留原文编号（`3a`），与已有 id 冲突时加 `L<NN>-`（NN = 给出清单时要写的 Part 号）；大纲派生 `P<plan>-<k>`；必做练习引入 `E<part>-<k>`；去重产生的深化条目 `<原 id>-d` |
| `text` | 归一化后的说法，≤60 字，一个可命名、可复现的产出 |
| `original` | 用户条目必填，**逐字保留**原文；拆分出的子条目都写父条目原文 |
| `parent` | 拆分时写父编号（`3` → `3a/3b/3c`）；父编号本身不单独成条 |
| `src` | `user` / `plan` / `exercise`（必做练习引入）/ `deepen`。**选做练习引入的概念不入账** |
| `from` | 具体来源：`user-list-2026-10-24`、`course_plan#3`、`part-02 练习 2` |
| `tag` | `main` / `foundation` / `mergeable` |
| `plan_ref` | 对应 `course_plan` 第几项；无归属 `null` |
| `status` | 六选一，见下表 |
| `at` | `taught` 必填：`part-NN.md#<该章 ## 标题原文>` |
| `depth` | `taught` 必填：`full`（构建章六项讲透）/ `foundation`（地基章）/ `ch0`（§0 承接章）/ `tier1`（档 1 融入） |
| `dup_of` | `duplicate` 必填：主条目 id，或已讲出处 `part-NN.md#<章节标题>` |
| `note` | `self-study` / `dropped_by_user` 必填（何时、因何）；推断回填写 `inferred` |

| `status` | 含义 | 同时必须满足 |
|---|---|---|
| `planned` | 列入大纲、按路线图还没轮到 | `plan_ref` 指向尚未写完的 plan 项 |
| `queued` | 被名额挤出、欠着的债 | 与 `metadata.knowledge_backlog` 一一对应 |
| `taught` | 已讲 | `at` 命中真实章节；`depth` 已填 |
| `self-study` | 用户**显式**降级，教程不承诺讲 | 同 id 记在 `research.md` 的 `## Self-study Backlog` |
| `dropped_by_user` | 用户**显式**删除（写前确认里删掉、闸门选 ③） | `note` 已填 |
| `duplicate` | 与已有条目或已讲概念**语义完全相同** | `dup_of` 已填 |

**流转**：`planned → taught / queued`；`queued → taught`；`planned/queued → self-study / dropped_by_user`（**只能由用户显式选择**：闸门 ②/③、写前确认里删除、收尾门禁 ②）；`self-study → queued`（用户说「把自学清单里的 X 讲掉」）；新条目可直接进 `duplicate`。**模型不得自行设置 `self-study` / `dropped_by_user`，不得删除条目。**

### 不变量（`ledger_check.py` 全部机械检查）

1. 每条恰有一个 `status`；`id` 不重复；条目只增不删。
2. `queued` 的 id 集合 = `knowledge_backlog` 的 id 集合（积压是账本的投影，不一致以账本为准）。
3. `taught` 的 `at` 指向 `parts` 里真实存在的 part 与 `##` 章节。
4. 写前计划确认里的每一条，写回后都有对应状态（覆盖 → `taught`、顺延 → `queued`、去重 → `duplicate`）。
5. 已写完的 plan 项名下不得残留 `planned` 条目。
6. **ID 镜像**：账本的 id 集合 = `metadata.syllabus_ids`（按字母序、只增不删）。**读账本前先核对**：镜像里有、账本里没有 → 条目被删，**停止写入**，按下文「损坏恢复」处理并报告缺失 ID；账本里有、镜像里没有 → 本次新增，写回时补进镜像。

### 谁读、谁写

| 操作 | 读 | 写 |
|---|---|---|
| 生成 | — | 创建：清单条目 + 全部 plan 项的大纲知识点（`planned`），写完 part-01 后更新状态 |
| 续写 | **按需**：有 shell 时只取未结条目（`grep -E '"status": "(planned\|queued\|self-study)"'`）+ 本次要动的条目，ID 冲突用 `syllabus_ids` 判断，改写用按行编辑；没有 shell 或只能整文件写回时读全文 | 本部分涉及条目的状态、`at`、`depth`；新增清单 / 练习 / 深化条目；本 plan 项大纲增删（经写前确认）；同步 `syllabus_ids` |
| 收尾 | 全文 | 门禁里用户选 ② 时改 `self-study`；不新增条目 |
| 复习 | 全文 | 不写 |
| 列表（单教程详情） | 只数各状态条数 | 不写 |

### 旧教程首次回填

账本不存在时，在写前计划确认里先给出回填结果，确认后写入（**不改任何已有 part**）：已有部分的构建章各成一条 `taught`（`depth: full`、`src: plan`、`note: inferred`），`covered_concepts` 里对不上章节的概念也补成 `taught`；`knowledge_backlog` 每条 → `queued`（沿用原 id）；`## Self-study Backlog` 每条 → `self-study`；尚未写的 plan 项各列 3-7 个大纲知识点 → `planned`。最后写 `syllabus_ids`。

### 损坏恢复

账本被删、JSON 损坏、或 ID 镜像发现缺条目时，按回填流程重建，报告「账本已按正文推断重建，原有 `dropped_by_user` / `duplicate` 记录无法恢复」，不要静默当空。`syllabus_ids` 告诉你原来有哪些 ID：回填后仍对不上正文的，逐个列给用户确认（`note: "原记录丢失，按镜像恢复"`），不得让它们消失。

## 2. 本部分讲哪些知识点

### 知识点来源（优先级，前面覆盖后面）

1. 本次用户指令里新给的清单；
2. `knowledge_backlog` 头部（= 账本 `queued`；先到先讲，带 `plan_ref` 的优先给对应 plan 项）；
3. 上一部分必做练习的承接（第 4 节三档）；
4. 账本中本 plan 项的 `planned` 条目（`course_plan` 下一项的大纲知识点）；
5. `continuity.next_hook`。

### 清单归一化（用户直接列知识点时必做）

1. **每条一个「可命名的产出」**：读者能用自己的话解释、能在代码里复现。「鉴权」是领域不是知识点 → 拆成「bcrypt 的 salt 与 cost」「JWT payload 放什么」「Guard 的位置」。
2. **打标签** `主知识点` / `前置（地基）` / `可合并`。前置走地基章节、不计入 4-7；可合并允许 1 章 2 条，但总数仍计入 7。前置超出本部分地基上限（生成 new 1-2 / adjacent 0-1 / familiar 0；续写最多 1）时，超出的转为构建条目占名额，名额也满就按原顺序入队——**不得因地基位满而丢弃**。
3. **保留原文编号**（`3a` / `3b`）。可以改写措辞使其准确，**不得合并、删减、替换**；原文 → 拆分的对照表写进写前计划确认。

### 名额分配

可用构建名额 = **7**。地基章节与 §0 承接章节不消耗名额（只计入「地基 + 承接 + 构建 ≤9」）；还债条目消耗名额。剩余名额按积压规模**反向**分配——积压越多，分给还债的越多：

| 积压条数 | 还给积压 | 给本次新清单（无清单时给本 plan 项的 `planned`） |
|---|---|---|
| 0 | 0 | 全部 |
| 1-4 | 2 | 剩余 − 2 |
| 5-9 | 3 | 剩余 − 3 |
| ≥10 | 4 | 剩余 − 4 |

- 无清单时，`planned` 不够填满的名额再给积压；本 plan 项装不下的 `planned` 转为 `queued`。
- §0 承接章永远排在正文最前，但不参与这张表；档 1 融入跟着它并入的那条知识点一起占位。

### 分批

归一化后 N 条、可用容量 C 条：N < 4 讲这 N 条、不凑数；N ≤ C 全讲；N > C 讲前 C 条，其余按原顺序入队（`course_plan` 不追加「补：」项）；**明确属于后续 plan 项的条目**（用户给的是整门课清单）记 `planned`、`plan_ref` 指向那一项，不占名额、不入队。

### 去重（只能「少记重复」，不能「少讲内容」）

| 比对结果 | 处理 |
|---|---|
| 与已讲概念（`covered_concepts`，含 `research.md` 的 `## Covered Concepts Archive`）**语义完全相同** | 不入队；记 `duplicate`，`dup_of` 指向已讲出处 |
| 与已讲概念**部分重叠** | **不得丢弃**：改写为「深化：<差异部分>」入队（`src: deepen`，id `<原 id>-d`） |
| 与积压条目**语义完全相同** | 合并：保留先入者 id，后来者原文编号追加到该条 `merged_ids`，后来者记 `duplicate` |
| 与账本 `planned` 条目**语义完全相同** | 按主条目优先级留一条，另一条记 `duplicate` |
| 部分重叠或拿不准 | 视为不同条目，分别处理 |

**主条目优先级**：`user` > `exercise` > `plan` > `deepen`；主条目继承两者中更早的 `plan_ref`。**拿不准一律按「不同」处理。** 每一次丢弃或合并都要先出现在写前计划确认里、再出现在覆盖回执里。

### 积压闸门（上限 14 条 = 2 个 Part 的量）

入队后 ≤10 正常；11-14 在播报里提示「积压已超过 1.5 个 Part 的量」；**会超过 14 时停止入队，在写前计划确认里给出三选一**：

```
⚠️ 知识点积压已达上限（14 条），本次有 k 条无法入队。三个选择：
① 扩 Part（默认）：把「<当前 course_plan 项>」拆成 2 个 Part，多花约 8-12 小时；
   我给出新的 course_plan 与分批方案，k 条全部入队并指向新拆出的项。
② 降级：k 条移入 research.md 的 `## Self-study Backlog`（保留原 ID），教程不承诺讲，随时可捡回。
③ 缩减：由你删掉优先级最低的 k 条。
默认执行 ①（你列出的知识点不被默认放弃）。回复编号可改。
```

选 ①：上限按新增 Part 数临时上调（每多 1 个 +7），k 条照常 `queued`、`plan_ref` 指向新项；`course_plan` **替换**被拆项，账本里指向它的条目同步改指。② / ③ **只能由用户显式选择**：② 记 `self-study`、③ 记 `dropped_by_user`，都不删条目。

### 重规划

触发任一：积压 > 14（选 ① 时闸门已附草案，不再重复）；连续 2 次续写净增 ≥3 条；同一 `plan_ref` 下 >7 条。输出草案（当前项拆成几项、各覆盖哪些条、新增几个 Part）；**用户确认后才改 `course_plan`**，未确认时继续按名额还债。

## 3. 向用户交代：写前确认、播报、回执

### 写前计划确认（动笔前，拿到回复再写）

触发任一：① **生成（总是）**——大纲（每个 plan 项 3-7 个知识点）是「课程是否讲全」的基准；② 用户列了知识点；③ 会有顺延、去重、闸门或重规划；④ 前置超出地基上限；⑤ 本 plan 项的 `planned` 需要增删改；⑥ 旧教程首次建账本。

都不满足（无清单、按大纲原样讲、无顺延与去重）时不多问。用户写了「直接写 / 不用确认 / `--no-confirm`」时跳过（生成的大纲确认除外），内容照样完整出现在回执里。**与同一操作的其他提问合并成一条消息**。

```
写前计划确认（part-NN）
⓪ 大纲（仅生成 / 大纲有变动时）：Plan 1 <标题>：P1-1 … ｜ P1-2 … ；Plan 2 …（后续项为预估）
① 清单归一化：3「鉴权」→ 3a bcrypt 的 salt 与 cost ｜ 3b JWT payload 放什么 ｜ 3c Guard 的位置
② 本部分讲（名额 7 = 还债 2 + 新清单 5）：K-1、K-2、3a、3b、4、5、6 ｜ 地基：… ｜ §0 承接：…
③ 顺延入积压：3c、7（预计 Part N）
④ 去重/合并：「JWT 签名」部分重叠已讲 part-02「JWT 结构」→ 入队为「深化：JWT 签名算法选择」
⑤ 闸门/重规划：<仅触发时贴出三选一原文与 course_plan 草案；默认 ①>
回复「可以」按此执行；也可以直接改：调顺序、增删条目、改拆分。
```

用户改了计划就按改后的写，不再二次确认。确认中被用户删掉的条目记 `dropped_by_user`；用户新加的按清单条目入账。

### 播报与覆盖回执（交付回复最前面）

```
积压：上次 a + 新入 b − 本次讲 c − 降级 e = 现在 f 条（core m）；自学清单 j 条。
覆盖回执：
本部分覆盖：3a→§1 ✅ · 3b→§2 ✅ · K-1→§3 ✅ · 5a→§0(承接) ✅
本次顺延：3c、7 → 积压（预计 Part N；正文「本部分不覆盖」已点名）
本次去重/合并：无 ｜ X ≈ part-NN「Y」→ 深化条目 K-9
章节完整性：计划 6 章 / 实写 6 章
试跑：runnable 7/7 通过 · 检查点 3/3 通过 · 未执行 0
账本：taught 18 · queued 2 · planned 23 · dropped_by_user 1 · duplicate 1（共 45 条）
```

- **有 shell 时，「本部分覆盖」与「账本」两行粘贴 `ledger_check.py --receipt`，「实写 N 章」取 `part_lint.py`，「试跑」行取 `trial_run.py`**——真实验证里模型自己填的章数填错过。
- `b` 是去重后的净新入数；等式对不上说明记账丢了条目，交付前查清。
- 写前计划里的每一条必须落在「覆盖 / 顺延 / 去重」之一；少一条就是漏讲，补写或入队后才能交付。
- 计划章数 ≠ 实写章数（输出被截断、后半被压缩）时补齐再交付。
- 无清单的常规续写同样给回执，只是没有归一化与去重行。

## 4. 练习承接三档

**必做题最多 2 道引入本部分没讲的新概念**，这几道要落进下面三档之一并入账（`src: exercise`）；其余必做题只用已讲内容。**选做题**可以引入新概念、不限量，但每道附「线索 + 官方文档入口」，**不入积压、不进账本**。

续写动笔前，把上一部分引入新概念的必做题逐题过这张表：

| 判定 | 落档 | 处理 |
|---|---|---|
| 它用到的知识点在本部分清单里，或是本部分某条知识点的直接子问题 | 档 1 融入 | 并进那一条，不额外占名额；账本 `depth: tier1` |
| 否，且承接章还有位置（≤2 条） | 档 2 承接章 | 进 §0 承接章；`depth: ch0` |
| 承接章已满 | 档 3 顺延 | 入积压（`queued`） |

- **档 1 的硬证据**：那一章必须有 ① 当时的错误/疑问（复述 ≤3 句）② 本部分知识点如何解释它 ③ 一个可运行验证。缺一降为档 2。
- **承接章**：标题写具体（`## 0. 先补上 Part 1 留的三个问题`），放在 `## 前置条件` 之后、第一个构建章之前，不放检查点之后；≤2 条，每条按「讲透」写（常见 150-400 字，**不设字数上限**）+ 1 个可运行验证，不写练习。它不占 4-7 名额，但计入总章 ≤9——占篇幅、占一次学习 session、占索引预算。

### 延后提醒（必须写进正文）

读者只读正文也要知道「这次没讲什么、下次大概在哪讲」。只写进积压不算提醒。

| 落点 | 写法 |
|---|---|
| 档 3 练习题面后 | *本题涉及的知识点（X，积压 ID `K`）不在本部分展开，预计 Part N 讲。* |
| 承接章末尾 | `本部分顺延：X（K）、Y（K'）（预计 Part N）。` |
| 「本部分不覆盖」 | 按积压 ID 点名顺延条目 |
| 清单分批时的开头 | `本部分覆盖清单第 a–b 条，剩余 k 条已顺延（Part N 起继续）。` |

Part 号是预计值；实际讲到某条积压时，在该章开头回指来源（「这就是 Part M 留下的 3c」），旧部分不回改。

## 5. 人工核对清单（没有 shell 时代替脚本）

写回之前逐条确认，任一不成立就修，不交付：

1. 知识点按本文第 2 节的来源优先级取；有清单时做过归一化、保留原文编号、对照表进了写前确认。
2. 超出容量的进了积压（不是 `next_hook`）；去重只丢了语义完全相同的，部分重叠改成了「深化：」；同义时按主条目优先级只留一条。
3. 积压 ≤14（选 ① 后按新增 Part 上调）；触到闸门给了三选一且默认 ①。
4. 必做题引入新概念 ≤2 道，各自落档；档 1 满足三件套；档 3 在正文至少两个落点有提醒且带积压 ID；选做题都有线索与文档入口。
5. 账本六条不变量逐条成立；本次新增 ID 补进了 `syllabus_ids`；没有条目被删除，也没有被模型自行改成 `self-study` / `dropped_by_user`。
6. 播报等式成立；写前计划的每一条都在回执里有着落；计划章数 = 实写章数。
