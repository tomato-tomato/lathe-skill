# 写作核心

本文件是 Lathe **写作型操作**（生成、续写、复习、收尾、面试文档）共用的单一事实源。仅这些操作需要读取；提问、标签、列表、扫描、验证等操作不加载本文件。

`<SKILL_DIR>` 指 SKILL.md 所在目录；`<TUTORIALS_DIR>` 指默认基础目录（`tutorials_base_path`）。

---

## 教程结构（单一事实源）

每篇教程（或系列的每个部分）遵循此结构，但章节*标题*必须特定于领域：

```
# [标题]

[引子——2 到 4 段]

## 你将构建什么
一段话。用控制性示例命名的具体最终状态。

## 前置条件
列表：需要安装的工具、读者应大致了解的知识。

## [具体的章节标题——命名本章节创造的东西]   ← 本部分共 4-7 个此类章节
为什么需要它。小块代码，每块标注插入位置。旁白或设计笔记。

## 检查点
> [!PREDICT]   ← 每部分恰好 1 个
> 运行之前：你预期会看到什么输出？
**运行以下命令验证：** + 预期输出 + 可能的错误

## 接下来
寄语或前向钩子：最后部分邀请读者走出铺设的道路；非最后部分用一段话命名未来部分将解答的未决问题，倾向悬念感。随后用平实散文（不是标注）提出**结尾反思**：挑本部分最重要的一个设计决策，要求读者解释*为什么*而非*是什么*，不替他们回答。

## 练习（编号，3-5 个，每个具体到 30 秒内可开始）   ← 3-5 个

## 来源（编号，格式：[标题](url) —— 一句话说明；超过约 5 条则分组）
```

每个部分以 *"在本部分结束时，你将拥有 [具体的东西]"* 开头，以检查点结尾。每个部分独立成篇。

**写作时的即时配额**（写的时候就按此控制，不要等写完再删）：非教学标注（HEADS-UP / ASIDE / NOTE / TIP）**合计最多 3 个**——写第 4 个之前先删一个；其中 HEADS-UP 最多 2 个；`[!PREDICT]` 恰好 1 个；正文具体章节 4-7 个；练习 3-5 个。数值的单一事实源见下方「标注类型」节。

**按操作的结构变体（登记在此，不在别处另行定义）：**

| 操作 | 结构差异 |
|------|----------|
| 生成 part-01 | 如上，无 `[!RECALL]` |
| 续写 part-NN（N≥2） | 顶部加 `> [!RECALL]` 节拍；`## 接下来` **之前**插入 `## 目标达成回顾` |
| 收尾 part-NN | 无 `## 检查点`（改为"回顾自检"）、无 `## 你将构建什么`；含全课程回顾、知识图谱、目标对照、练习方向、寄语（详见 extend.md 收尾模式） |
| 复习 part-NN-review | 完全独立的回顾结构，不遵循上表（详见 review.md） |
| 面试文档（复习/生成/续写产出的附加文件） | **完全独立的问答结构，不遵循本表**；**只对教学部分产出**（定义见 `interview.md`，此处不复述）。本文件对其**仅**提供「检索预算数值」与「有据可依或标记」不变量，**不提供**结构、标注配额与交付前自检 |

## 标注类型

| 标注 | 用途 | 频率 |
|------|------|------|
| `> [!PREDICT]` | 检查点前的预测提示 | 每部分 1 次 |
| `> [!RECALL]` | 第 N≥2 部分顶部的间隔检索 | 每部分 1 次 |
| `> [!HEADS-UP]` | 即将踩坑的警告 | 按需，**≤2 次/部分** |
| `> [!ASIDE]` | 词源、故事等旁白（1-2 句） | 按需 |
| `> [!DESIGN-NOTE]` | 多段落的"为什么"讨论 | 章节末尾 |
| `> [!UNVERIFIED]` | 无法确认的关键声明 | 诚实标记 |
| `> [!NOTE]` | 中性补充信息 | 按需 |
| `> [!TIP]` | 便捷技巧 | 按需 |

**硬上限（写完后必须自检，见文末"交付前自检"）：** 非教学性标注（HEADS-UP、ASIDE、NOTE、TIP）每部分**合计不超过 3 个**；其中 HEADS-UP 单项不超过 2 个。在上限内仍须宁缺毋滥——标注是强调手段，用多了等于没用。信息若能进正文散文，就不要包装成标注。

## 不变量（始终生效，与 voice 无关）

这些规则在**每种** voice 和**每个**写作操作中都成立：

- **有据可依或标记——绝不虚张声势。** 每个关键声明有来源或 `[!UNVERIFIED]` 标注。
- **在陷阱发生前命名它们。** 使用 `[!HEADS-UP]` 警告即将踩坑的内容。
- **先展示错误版本，再展示修复。** 演示诱人但有问题的方法，然后展示修复。
- **定义术语，然后给出内行名称。** 粗体标记规范术语，同义词紧随。
- **使用领域真实名称。绝不用 `foo`/`bar`。**
- **每次都用具体数字。** "48000"比"很快"更有记忆点。
- **指定异常输入。** 引入处理器后，立即回答"几乎匹配但不完全匹配的输入会怎样？"
- **在关键事实首次出现时内联引用。** 深度链接到具体章节，而非首页。

**优先级绝对——不变量获胜。** voice 仅控制语气；绝不放松准确性、研究、引用或验证规则。

## 先研究（起草之前）

在写下任何一句话之前，**先去阅读**。使用网络搜索和抓取工具找到该主题的权威来源——官方文档、规范/RFC、原始论文、源代码、知名的深度文章。不要从记忆中重建。

**检索预算（生成与续写统一，不得各自放宽）：**

| 项目 | 上限 | 触发条件 |
|------|------|----------|
| 搜索（只看标题与摘要） | **5 次** | 默认执行 |
| 全文抓取 | **2-3 次** | **仅当**某个关键事实的摘要不足以支撑时才执行——定向抓取该页的相关章节 |
| 全文抓取下限 | **无** | **不设下限：摘要够用就 0 次抓取** |

**分级执行：** 先用 1-2 次搜索建立事实骨架；只有当某个关键事实（精确 API / 函数签名、默认值、标志名、版本号、采样率、页面大小、语义保证、错误信息）的摘要不完整时，才升级为定向抓取。

> **"研究充分"的判据是"每个关键事实都有来源或已标记 `[!UNVERIFIED]`"，不是"抓了 N 个页面"。** 少抓不是放宽，多抓也不等于尽责。

- **摘要优先，按需深读：** 先从搜索结果的标题与摘要中提取事实，只在摘要不够时才抓全文。
- **针对性抓取：** 全文抓取时带上明确的问题（如"`comptime` 的零开销保证"），只提取相关章节，避免整页内容进入上下文。
- **为关键事实而阅读：** 精确的 API/函数签名、默认值、标志名称、版本号、采样率、页面大小、语义保证、错误信息、历史声明。在每个事实旁记录 URL——深度链接到具体章节或锚点。
- **让行文基于所读而非所忆。** 当来源与记忆矛盾时，来源获胜。找不到来源的关键声明用 `[!UNVERIFIED]` 标记。
- **保留查阅过的 URL 列表。** 内联引用关键来源，在 `## 来源` 中列出，并记录到 `metadata.json` 的 `sources`。
- **续写时不重复研究已覆盖内容：** 只研究**本部分新引入**的内容；已有部分建立的事实直接沿用，不再重新查证。
- **没有网络工具？** 用一句话告诉用户，然后更保守地写作：减少精确数字的断言，对关键未知项使用 `[!UNVERIFIED]` 标记。

## 预检（私下进行，不让用户审批）

在写下任何一句话之前，在脑中确定：

> **本步只做"写前决策"，不做核对。** 写后核对见文末"交付前自检"——两者分工不重复：预检产出"写什么"（示例、数字、隐喻、寄语、练习方向），自检只负责"数一数、对一对"。**来源的查阅属于上方"先研究"，此处不重复确认。**

- **版本-特性一致性。** 示例代码使用的语法/特性/API 在锁定的工具链版本下成立；配置代码块（如 `Cargo.toml` 的 `edition`、依赖版本）与锁定版本一致。不确定特性的引入版本时查官方 changelog，绝不凭记忆断言——这类冲突（如 edition 2024 配 2021 语义的代码）应在写作时拦截，而非留到验证或读者手中。
- **控制性示例。** 选择一个具体的产物并贯穿始终。如 *"一个 4 声部减法合成器演奏持续的 A 小调三和弦"* 或 *"一个名为 `pebble` 的键值存储，能在 `kill -9` 后存活"*。不要中途切换。续写时从 `continuity` 摘要读取，精确复用。
- **具体数字。** 采样率、缓冲区大小、页面大小、表基数、延迟预算——领域提供的任何参数。
- **一个控制性隐喻（可选但有力）。** 一座山。一条流水线。一间厨房。至少三个章节过渡中使用，然后*明确告别它*。
- **结尾寄语。** 你希望读者准备好在你教的内容*之外*做什么？
- **练习方向。** 定下 3-5 个练习的**方向**（每个具体到有动力的读者可以在 30 秒内开始）；**数量核对归自检**。

## 风格标杆与主锚点

voice 控制语气，**风格标杆控制写作节奏和结构选择**。每个教程锁定**一个主锚点作者**，记录在 `metadata.json` 的 `style_anchor` 字段。

- **生成时：** 读取 `<SKILL_DIR>/references/style-benchmarks.md` 的场景侧重表，按主题匹配主锚点，将其 id（如 `nystrom`、`amit-patel`）写入 `style_anchor`。
- **续写/复习时：** 直接从 `metadata.json` 读取 `style_anchor` 并沿用，**不再读取 style-benchmarks.md**。字段缺失的旧教程：按已有部分的实际写作节奏推断一个 id，本次写回 metadata 时补上（仅此一次需要读 style-benchmarks.md）。

主锚点指导三件事：章节如何组织（Nystrom 式独立成篇 vs Ciechanowski 式逐层拆解）、代码演示的节奏（Amit Patel 式渐进可运行 vs Sam Who 式精炼配可视化）、与读者的距离（Julia Evans 式亲切聊天 vs plainspoken 式精确陈述）。

## voice 的应用

- **plainspoken**（默认）—— 直接、精确，坦承由机器生成；平实散文，短句陈述，不虚构人格。**默认情况直接按本行摘要写作，不要读取 voice.md。**
- **companion / craftsman** —— 仅当 `metadata.json` 的 `voice` 字段为这两者时，才读取 `<SKILL_DIR>/references/voice.md` "内置 voice"一节获取完整规范（单一事实源）。
- **自定义 voice** —— 读取 `<TUTORIALS_DIR>/voices/<名称>.md` 获取规范。

续写时**不重新选择 voice、不漂移**——从 metadata 读取并沿用。

## 内容与教学法

以下是不变量的落地写法示例。

**内联引用——对比：**
> ❌ "Zig 的 `comptime` 在编译时运行代码，产生零运行时开销。"
> ✅ "Zig 的 [`comptime`](https://ziglang.org/documentation/master/#comptime) 在编译期间运行普通 Zig 代码。结果被作为静态数组烘焙进二进制文件——[零运行时开销，这是语言保证](https://ziglang.org/documentation/master/#comptime)。"

**预测节拍——对比：**
> ❌ *（无预测；读者冷启动运行命令）*
> ✅ `> [!PREDICT]` *运行之前：正弦表有 1024 个条目。`@sizeOf(@TypeOf(sine_table))` 会输出什么？*
> *（答案——4096 字节——更有冲击力，因为读者先承诺了一个数字。）*

**间隔检索——对比（第 N≥2 部分开头）：**
> ❌ "在第 2 部分我们将添加滤波器。先快速回顾……"
> ✅ `> [!RECALL]` *继续之前快速回忆：`write_pos % BUFFER_SIZE` 实现了什么？*
> *（读者必须重建答案——检索会加强记忆。）*

**渐隐脚手架——对比：**
> ❌ "现在添加 Release 阶段："*（后面是完整写好的代码块）*
> ✅ "你已经看到 `Attack` 如何在 `attack_samples` 内从 0 斜升到 1。`Release` 做镜像——现在用相同循环形状写出来。"

**结尾反思——对比：**
> ❌ "做得好！你构建了……"
> ✅ "用两句话说明，为什么环形缓冲区在这里优于 `sync.Mutex` 保护的切片？"

### 概念锚定——从已知知识引申

介绍重要概念时，除了详细介绍本身，还要**从读者已知的知识体系出发引申讲解**，让新概念锚定在旧知识上。锚点按 `metadata.json` 的 `experience_level` 字段选择（生成时询问并写入，续写时读取——不要重新询问）：

- **`beginner`** → 用日常生活经验或最基础的编程概念做类比；
- **`familiar`** → 类比本领域相邻的已知概念；
- **`experienced`** → 直接对照读者熟悉的其他语言/系统机制，指出对应关系与差异。

字段缺失的旧教程：按已有部分实际使用的类比深度推断，本次写回 metadata 时补上。

**对比：**
> ❌ "所有权是 Rust 管理内存的机制：每个值有唯一所有者，所有者离开作用域时值被释放。"
> ✅ "如果你写过 C++，可以把所有权理解为'编译期检查的 `unique_ptr`'：每个值有唯一所有者，所有者离开作用域时资源自动释放——Rust 只是把这项检查从运行时移到了编译期，零运行时开销。"

约束：类比只是桥梁——搭上桥后必须回到本语言的精确术语；类比失效处（行为有差异）用 `[!NOTE]` 一句话点明，不误导。每部分锚定 **2-3 个**最重要的概念即可，不要每个术语都强行类比。

## 旁白和设计笔记

**旁白** —— 简短、内联，一两句。词源、故事、"顺便说一句"。
```markdown
> [!ASIDE]
> "Lex" 来自希腊语 *lexis*，意为"词语"。
```

**设计笔记** —— 多段落的关于*为什么是这样*的岔开讨论。放在章节**末尾**，绝不在步骤中间。
```markdown
> [!DESIGN-NOTE]
> **为什么用环形缓冲区而不是通道？**
> 关于替代方案的几句话……
```

## 视觉元素

目标是**每个部分一个图表**，仅在某个时刻确实受益时使用。工具：

- **Mermaid `flowchart`/`graph`** —— 流水线、决策分支
- **Mermaid `sequenceDiagram`** —— 请求/响应
- **Mermaid `stateDiagram-v2`** —— 协议状态、生命周期
- **Mermaid `erDiagram`** —— 模式
- **Markdown 表格** —— 比较替代方案
- **代码块中的 ASCII 艺术** —— 内存布局、字节结构

节点上限约 10 个。将图表放在解释它的文字旁边。

## 代码

- 每个代码块前一句话，告诉读者先看什么。
- 代码块 3-15 行，完整的小文件除外。
- 修改时，指明接缝：*"在 `process_buffer` 内部，紧接 voices 循环之后："*。
- 不解释的 `...` 省略。代码完整到可以运行。
- **渐隐脚手架：** 第一个代码块完整展示。最后一两个切换为填空模式：命名读者见过的模式，要求读者写出下一个实例。

## 交付前自检（写完之后，落盘之前）

**核对方式：逐项计数 / 查找，不要重读全文。** 每写完一个 `## ` 章节，就地核对该章节的标注数、代码块行数与内联引用；全文写完后只做下面这些**跨章节**的项：

1. **标注配额（数出现次数）**：`[!HEADS-UP]` + `[!ASIDE]` + `[!NOTE]` + `[!TIP]` 合计 ≤ 3？`[!HEADS-UP]` ≤ 2？`[!PREDICT]` 恰好 1 个？（N≥2 部分）`[!RECALL]` 恰好 1 个？超限就把最弱的标注改写进正文散文或直接删掉。
2. **结构齐全**：对照上方"按操作的结构变体"表，数一遍该有的 `## ` 小节是否都在、顺序是否正确。
3. **练习数量（数编号）**：3-5 个。
4. **来源对应**：把 `## 来源` 里的链接与正文内联链接做一次**查找比对**——只列了正文真正引用过的，且正文里的链接都在来源里。
5. **版本一致（查找比对）**：代码块与配置块中的版本号，与 `tools` 锁定值一致。
6. **禁用词（查找）**：无 `foo`/`bar`，无企业腔与套话开头。
7. **概念锚定（数处数）**：2-3 个重要概念做了锚定，锚点与 `experience_level` 匹配。

**发现超限就就地删减，不要落盘后再补救。** 不向用户展示这份清单，只在有修正时用一句话说明。
