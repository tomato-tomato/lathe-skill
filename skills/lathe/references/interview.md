# 面试文档

为教程生成「面试要点」文档：**每个 slug 一个 Markdown 文件**，按**教学部分（Part）分章**，每条要点给出「一句话回答 → 展开 → 追问点 → 我的项目里」的解答，供面试前突击复习。

**先读共享文件：** 本操作需要 `<SKILL_DIR>/references/writing-core.md` 的**检索预算数值**（延伸研究用）与「有据可依或标记」不变量；**不需要**其中的教程结构、标注配额与交付前自检——面试文档有独立结构，见下方。

**本文件是「教学部分」定义的单一事实源**——`extend.md` 等文件一律**引用**，不复述。

## 触发

| 触发 | 说明 |
|---|---|
| `/lathe 面试\|interview <slug> [part-NN]` | 快捷形式：整课程或指定部分 |
| `/lathe 复习\|review <slug> 面试\|interview [part-NN]` | 从复习进入（`review.md` 会转到这里） |
| `/lathe 续写\|extend <slug> 面试` | 续写完成后同步（文档不存在时创建） |
| `/lathe 续写\|extend <slug>` | 文档**已存在**时**自动同步**本次部分（见「续写联动」） |
| `/lathe <主题> 面试` | 生成教程时同步产出 Part 1 分段 |

**消歧规则：**

- `面试` / `interview` 必须是**独立 token**（前后为空白、行尾或标点）；
- 作为**首个 token** 时（`/lathe 面试 <slug>`），**只有后跟一个已存在的 slug 才进入本模式**；否则视为主题——`/lathe 面试题生成器怎么做` 走正常生成；
- 不确定时**先问**，不要默认进入面试模式。

## 路径解析

面试文档位置记录在 `~/.lathe/config.json`，两个字段**均为可选**（缺失即走下一档，旧 config 无需迁移）：

```json
{
  "interview_base_path": "~/Code/agent-transition/interview",
  "interview_paths": {
    "nest-kb-service": "~/Code/agent-transition/interview/阶段一_NestJS与服务端基础"
  }
}
```

| 顺序 | 条件 | 文档路径 |
|------|------|----------|
| 1 | `interview_paths[<slug>]` 存在 | `<该目录>/<slug>.md` |
| 2 | `interview_base_path` 存在 | `<该目录>/<slug>.md` |
| 3 | 都没有 | `<教程目录>/<slug>/interview.md` |

**一个 slug 一个文档，文件名 = slug**（第 3 档落在教程目录内，故用 `interview.md`）。

## 位置确认（仅文档不存在时）

| 场景 | 行为 |
|------|------|
| **文档不存在** | **必须询问**：展示解析出的默认路径并确认——*"面试文档将保存到 `<默认路径>`，要换个位置吗？"*。用户给出新位置 → 本次写到那里，并**登记 `interview_paths[<slug>]`**（仅当新位置 ≠ 第 2/3 档解析结果时才登记）。**不得静默跳过**——即使在没有选择框 UI 的终端 Agent 里，也要以纯文本问出。 |
| **文档已存在** | **不询问**：沿用其当前位置，仅在结果里一行播报路径。 |
| 用户主动要求迁移 | 按指定位置迁移，并更新 `interview_paths[<slug>]`。 |

## 教学部分（单一事实源）

```
教学部分 = metadata.json 的 parts 数组中的文件，且同时满足：
           ① 文件名不含 `-review`      （排除复习材料）
           ② 文件含 `## 检查点`        （排除收尾总结部分）
回退：若按 ② 排除后集合为空（明显异常），退化为「仅按 ① 排除」。
```

| 文件类型 | 是否产出面试分段 | 理由 |
|----------|------------------|------|
| `part-01.md` 等**教学部分** | ✅ **唯一来源** | 只有它们承载「面试官可能问、且值得深挖」的教学要点 |
| `part-NN-review.md` **复习材料** | ❌ **不产出** | 回顾性材料（逐部分回顾、自测题、重跑检查点），**不含新要点** |
| 收尾**总结部分** | ❌ **不产出** | 全课程回顾 + 知识图谱 + 目标对照，同样不含新要点 |
| 面试文档自身 | ❌ 不作为来源 | 防止自我引用 |

**跳过复习材料与总结部分时：不提示、不报错。**

## 遗漏检测与补写确认

```
已覆盖集合 C = grep -oE '^# 第.+部分 · Part [0-9]+' <面试文档>   （文档不存在则 C = ∅）
教学部分集合 T（见上节）
遗漏集合 M = T \ C
```

**判据：只有「面试文档已存在、但覆盖不全」才需要确认。**

| 触发 | 文档状态 | 行为 |
|------|----------|------|
| 整课程（不带 `part-NN`） | **不存在** | **不确认**——直接按规则生成 |
| 整课程 | 已存在且**完善**（`M` 为空） | **不确认**——报告「已是最新」，询问是否重写某个 Part |
| 整课程 | 已存在且**不完善**（`M` 非空） | ⚠️ **必须确认**（是 / 否） |
| 单 Part（带 `part-NN`）或「续写 + 面试」建文档 | 任意，`M` 非空 | **必须确认**（二选一） |
| 续写自动同步 | 已存在 | **不确认、不扩大** + 末尾一句缺口提示 |

**整课程确认（是 / 否）：**

```
面试文档已存在（当前覆盖 Part 4–5），但尚缺 <k> 个教学部分：Part 1、2、3。
按规则将补全这些部分（已有分段保持不动）。

是否继续？[Y/n]
```

- 确认 → 目标集合 = `M`；
- 拒绝 → **什么都不做**，只报告现状。

**单 Part 确认（二选一，默认 1）：**

```
该课程有 <k> 个教学部分尚无面试分段：Part <列表>。
你希望：
1. ✅ 补写全部 —— 补齐 Part <列表>，并写入当前 Part <N>（完善整个面试文档）
2. ➕ 只写当前 —— 仅写入 Part <N>，历史缺口保留
请回复编号（默认 1）。
```

- 选 **1** → 目标集合 = `M ∪ {当前 Part}`；
- 选 **2** → 目标集合 = `{当前 Part}`；**缺口保留**，下次任何面试写入时仍会被检测到并再次询问。

## 协议

```
0. 解析教程位置；metadata.json 缺失/损坏 → 先走 metadata.md「metadata.json 自愈」。
1. 读 metadata：title / goal / tools / repo / local_project_path / language /
   parts / continuity.part_titles / sources。
2. 计算【教学部分】集合 T（见上）。
3. 解析面试文档路径（三档）。
4. 【仅当文档不存在】确认存储位置（见「位置确认」）。
5. 解析已覆盖集合 C，计算遗漏集合 M。
6. 【遗漏处理】按触发路径分派（见上表）。
7. 文档不存在 → 按下方模板创建（含头部与两张固定表）。
8. 确定本次目标集合，按 Part 编号升序排列；为空 → 告知「已是最新」并询问是否重写某个 Part。
9. 逐个 Part 生成分段：
   a. 读该 part 全文（整课程模式逐个处理）；
   b. 提炼【课程】/【课程+延伸】要点；
   c. 按检索预算做延伸研究，补【延伸】要点；
   d. 每条要点标注课程出处；延伸要点附来源。
10. 追加写入：新分段按 Part 编号升序插入文档末尾；
    头部「本课程的进度」表逐行更新（各 Part 的要点数与状态）。
11. 首次创建且位置 ≠ 第 2/3 档解析结果 → 写入 config 的 interview_paths[<slug>]。
12. 告知用户：文档路径、本次新增/更新的 Part、要点条数与来源构成（课程 a · 课程+延伸 b · 延伸 c）；
    若用户选了"只写当前"，补一句缺口提示（"仍缺 Part 1–2，下次可补齐"）。
```

## 续写联动（由 extend.md 触发）

- 续写时**面试文档已存在** → 续写完成后**自动同步**本次刚写入的那个 Part（**无需参数**），已有分段不动；
- 续写时**文档不存在** → 静默跳过，**不创建文件**；带 `面试` token 时才创建（创建前须走「遗漏检测与补写确认」）；
- **收尾模式不产出面试分段**（总结部分不是教学部分）；
- **逃生阀**：`不同步面试` / `--no-interview` 可跳过本次同步。

## 文档模板

### 头部（首次创建时写入；已存在时原样保留，只更新「状态」与日期）

```markdown
# <slug> · 面试要点

> **教程**：<metadata.title>
> **教程目录**：`<教程实际目录>/<slug>/`
> **代码仓库**：`<local_project_path 或 repo，均缺则 —>`
> **技术栈**：<tools 逐条 name + version>
> **状态**：<如「Part 1 已解答（14 条）」> ｜ 最后更新：<YYYY-MM-DD>
>
> **所属阶段**：<手填>
> **对应计划**：<手填>
> **本阶段可投岗位**：<手填>

**使用方法**：盖住答案，只看问题。能说出「结论 → 原理 → 取舍 → 我的项目」四层，才算掌握。

> **本文件只覆盖本项目（`<slug>`）的面试要点。** 阶段总览与状态总表在 `<总览文档相对路径>`。
```

> 标 `<手填>` 的三项 lathe 无法推断，留占位；已存在时**原样保留**。最后一行同样由用户手填。

### 两张固定表（首次创建时写入，此后只更新「本课程的进度」的数据行）

```markdown
## 本课程的进度

| 课程 | 标题 | 要点数 | 状态 |
|---|---|---|---|
| **Part 1** | <part-01 一级标题> | 14 | ✅ 已解答 |
| Part 2 | <未生成则写「待生成」> | — | ⬜ |

> 新课程生成后，在下方追加新的「第 N 部分」，不要打散已有内容。

## 要点来源标注

| 标注 | 含义 | 背诵注意 |
|---|---|---|
| **【课程】** | 该 Part 直接讲过，有对应代码或取舍讨论 | 可放心背，「我的项目里」是真实做过的 |
| **【课程+延伸】** | 该 Part 提到了但没展开；解答里补了面试常见的追问 | 背之前先确认延伸部分自己在项目里验证过 |
| **【延伸】** | 该 Part 只有一两句话或完全未提，解答是按面试需要补写的 | **属于预习**，等后续课程或自己实践后再当"我做过"来讲 |

> 为什么要区分：面试官追问细节时，「我做过」和「我看过」是两种状态。把【延伸】的内容说成自己的项目经验，一问就穿帮。

**每条解答都标明「课程出处」**——回到课程对应章节回忆上下文，理解过的内容比背下来的记得久。
```

### 每个 Part 的分段（每次追加一个）

````markdown
# 第<中文数字>部分 · Part <阿拉伯数字>：<该 Part 一级标题>

> **课程文件**：`<教程目录>/<slug>/part-<NN>.md`（<M> 行）
> **本部分覆盖的章节**：《章节一》→《章节二》→《章节三》
> **要点构成**：课程 <a> 条 · 课程+延伸 <b> 条 · 延伸 <c> 条

---

## <N>-1 <问题> 【课程】

> **课程出处**：Part <N> ·《章节名》

**一句话回答**：<一到两句，直接给结论>

<展开段：用主题化小标题（如 **原理** / **为什么切这么细** / **四个理由** / **工作流程**），
 可含代码块与对照表。数量按内容定，不固定；不要写「展开」这个字面标签。>

**追问点**：<面试官可能接着问什么 + 答案；也可写成 `**追问点：<具体问题>**`。
 没有值得写的追问时整段省略。>

**我的项目里**：<有真实锚点 → 写具体文件与做法；无锚点 → 写「本阶段课程中的做法：……」；
 完全无支撑 → 可整段省略。>

---

## <N>-2 <问题> 【延伸】

> **课程出处**：Part <N> ·《章节名》（课程仅提及 X；本条的 Y 部分为按面试需要补写）

**一句话回答**：…

<展开段：同上>

**追问点**：…

**尚未实践**：<【延伸】类不得写「我的项目里」。两种写法二选一：
              ① 有真实锚点 → 「本阶段课程中的做法：……」；
              ② 无锚点 → 「尚未实践」。>

> **延伸来源**：<url1> · <url2>
````

## 格式硬约束

1. Part 分段标题**必须**是 `# 第<中文数字>部分 · Part <阿拉伯数字>：<标题>`（如 `# 第一部分 · Part 1：服务骨架与请求管线`）——覆盖状态靠它推导，格式漂移会导致重复生成。
2. 要点标题**必须**是 `## <N>-<k> <问题> 【标注】`；`<N>` 为该 Part 的阿拉伯数字序号，`<k>` 从 1 起连续。
3. **必写层只有两层**：`**一句话回答**` 与 `> **课程出处**：…`。
4. **展开层用主题化小标题**，**不得写「展开」这个字面标签**。
5. `**追问点**` 与 `**我的项目里**` **按内容取舍，没有就不写**——**不因缺这两层判为不合格**。
6. **【延伸】类的末层固定为「尚未实践」**（有真实锚点时才写「本阶段课程中的做法：……」）——**禁止写成个人经验**。
7. 表格列数/对齐与既有分段保持一致（不重排已有表格）。
8. 分段之间用 `---` 分隔。
9. 【延伸】类要点必须带 `> **延伸来源**：` 行；无法确证的结论在正文里标 `[!UNVERIFIED]`。
10. 文档末尾若已有用户手写的 `## 附：…` 小节（如「概念对照笔记」），**原样保留、不修改、不重排**。

## 纪律

- **不编造**：「我的项目里」**存在时**只能是教程里真实出现过的文件/做法；`local_project_path` / `repo` 缺失时写「**本阶段课程中的做法：……**」，**不得写成个人经验**。**无任何支撑时可整段省略**。
- **【延伸】要点不得伪造项目经验**：末层只能写「本阶段课程中的做法」或「**尚未实践**」。
- **每条要点必须有课程出处**。
- **三态标注必须真实**：【课程】/【课程+延伸】/【延伸】。
- **来源限定**：只从**教学部分**提取；复习材料、收尾总结部分、面试文档自身不作为来源。
- **不改动**：不修改教程正文、`metadata.json`、`parts`、`status`、`tags`。
- **要点数量软引导**：参考 5–15 条/Part，按「面试官可能问、且值得深挖」取舍，**不设硬上限**。
- **作用域自限**：本文件的研究/标注纪律**只约束面试文档**；不得据此修改或"顺手统一" `writing-core.md` 的研究预算与不变量。
- **绝不静默漏 Part**：任何写入前先算 `M`；除整课程路径外，任何补写都须经用户确认；用户选"只写当前"后，缺口要在结果里提示并在下次再次提出。

## 延伸研究

- **默认联网研究**，为每个 Part 补出面试常见的追问（【延伸】类）；
- **预算沿用** `writing-core.md` 的检索预算**数值**（搜索 ≤5 次/Part；全文抓取 ≤2–3 次/Part，无下限）；
- **不重复教程已做的研究**：教程 Part 的 `## 来源` 与 `metadata.sources` 已建立的事实直接沿用，不重新查证；只研究**新引入的面试追问角度**；
- **【延伸】要点必须有来源**（`> **延伸来源**：` 行），无法确证时标 `[!UNVERIFIED]`；
- **【延伸】占比软引导 ≤ 1/3**：它是预习内容，不是主体；超出时在「要点构成」里如实统计；
- **无网络工具时降级**：一句话告知用户，本次**跳过【延伸】**，只产出【课程】+【课程+延伸】。

## 边界

- 唯一写入操作：创建/追加面试文档、更新 `config.json` 的 `interview_paths`。**不修改任何教程文件。**
- **面试文档不是 part**：绝不写入 `metadata.json` 的 `parts`，绝不命名为 `part-NN*.md`——`verify` 因此不会尝试执行它，`list` 与续写的编号推导也不受影响。
- 保持会话。
