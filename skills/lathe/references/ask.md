# 提问教程内容

回答读者关于已存储教程某个部分的问题，回答要扎根于该教程实际构建的内容。

**触发格式：**
```
/lathe 提问|ask <slug> [part] <读者的问题>
```

解析 slug、部分（可选）和问题。中文关键词 `提问` 和英文关键词 `ask` 等价。

**部分参数宽松匹配：** `part-01.md`、`part-01`、1 均接受，统一解析为 `part-NN.md`。**省略部分参数时**，根据问题内容在各部分中自动定位最相关的部分：先读 `metadata.json`，用 `parts` 列表与 `continuity.part_titles`（已有时无需打开文件）判断；`continuity.covered_concepts` 也能提示某个概念属于哪个阶段。仍无法判断时，用 `grep` 在各部分中检索问题里的关键词定位；还不行就列出部分列表让用户选择。**不要为了定位而逐个读完全部部分。**

## 协议

1. **定位并阅读目标部分。** 按 `<SKILL_DIR>/SKILL.md`"教程位置解析规则"找到该教程目录，阅读其中的 `<part-NN.md>`。回答时遵循教程的语言（`metadata.json` 的 `language` 字段；若 `metadata.json` 缺失，直接按部分文件的实际语言回答，并在末尾顺带提醒可按 `<SKILL_DIR>/references/metadata.md`"metadata.json 自愈"重建索引）。当问题跨部分或依赖更早的设置时，阅读同目录下的**相关**部分——连续性在这里同样重要，但只读确实相关的那几个，不是全部。

2. **回答要扎根于本教程的具体产物**——相同的控制性示例、相同的数字、教程使用的相同 voice。读者问的是*他们的*合成器 / *他们的*键值存储，而不是抽象的主题。不要从头重新教授整个主题。

3. **指向教程，不要重新推导。** 优先"看 §3 中的 `process_buffer` 循环——那里的取模在做 X"，而非全新的从零解释。你是站在读者身旁、看着他们正在阅读的页面的向导。

4. **对缺口保持诚实。** 如果问题暴露了教程出错、含糊或用 `[!UNVERIFIED]` 标记的内容，直接说明——不要掩饰。这比自信地挥手更有用。**确认是错误时，进入下方「勘误确认」**；只是含糊或可以讲得更好，回答里说明即可，不提议改正文。

5. **保持参与**以回答后续问题。这是一场对话，不是一次性回复。

## 勘误确认（发现错误时，需用户手动确认）

**什么算错误：** 事实错误（API/签名/默认值/版本与官方来源不符）、代码按教程步骤无法编译或运行、与 `fixed_numbers` 或前后文矛盾的数字/符号、缺了运行必需的步骤。**不算：** 措辞偏好、想补充新知识点（那是续写的事，可建议 `/lathe 续写 <slug> <指导>`）。

事实类错误先用 1 次定向搜索/抓取核对官方来源；核对不了的不提议修改，只在回答里标明存疑。

先回答问题，再在回复末尾单独给出确认块。**这一步只提议，不写任何文件：**

```
⚠️ 发现教程错误（需要你确认才会处理）
位置：part-NN.md §<章节>（第 <行> 行附近）
问题：<一句话说明错在哪>
依据：<来源链接 / 编译错误 / 与 part-MM 矛盾之处>
原文：<要改的原文片段，原样摘录>
修正：<修正后的片段>
影响：<只改这一处 / 还牵涉 part-MM 的 X>；改正文后该部分需重新验证。

请回复以下之一（只回复「好」「嗯」不算确认）：
1. 确认修改 —— 原地修正 part-NN.md，并记入 research.md 的 Errata
2. 只记勘误 —— 正文不动，记入 Errata，下一次续写在 RECALL 或相关章节更正
3. 不处理
```

- **只有用户回复编号 `1` / `2` 或原样写出「确认修改」/「只记勘误」才执行**；其他回复（含「好」「可以」「嗯」）一律当作未确认，可再问一次，不得自行处理。
- 宿主支持选择框（如 AskUserQuestion）时用选择框呈现这三项，不预选任何一项。
- 一次回答发现多处错误时，逐条编号列出，允许用户只确认其中几条（如「确认 1、3」）。
- 已经在学、不想改原文的课程，建议用选项 2（正文冻结，更正写进后续部分）。

**用户确认后的执行：**

| 选项 | 写入 |
|---|---|
| 1 确认修改 | ① 只替换确认块里的「原文」片段，不顺手改其他内容、不改 voice 和结构；② 该部分的验证状态横幅换回「未验证」模板（`lathe:verify-status` 标记块，写明「勘误于 <日期>」）；③ `metadata.status` 为 `verified` 时改为 `unverified`（`completed` 保持不变）；④ 若修正涉及 `fixed_numbers` / `covered_concepts` 的措辞，同步更新这些字段；随后刷新 `continuity.updated_at`（这次修改是已知改动，不需要让续写按手工编辑重建）；⑤ 追加一条到 `research.md` 的 `## Errata` |
| 2 只记勘误 | 只追加一条到 `research.md` 的 `## Errata`，处理方式写「只记勘误」；不动正文、横幅和 `status` |
| 3 不处理 | 不写任何文件 |

`## Errata` 条目格式（`research.md` 不存在时创建它，小节顺序见 `metadata.md`）：

```markdown
## Errata

- <YYYY-MM-DD> `part-NN` §<章节>：<原文要点> → <修正后>（原因：<一句话>；处理：原地修正 / 只记勘误）
```

执行后告诉用户改了哪些文件；选 1 时提示运行 `/lathe 验证 <slug>` 重新验证该部分。

## 边界

- **默认只读、对话式。** 唯一的写入是上方「勘误确认」中**用户显式确认后**的处理；写入范围仅限：目标 `part-NN.md` 中被确认的那一处片段及其验证状态横幅、`research.md` 的 `## Errata`、`metadata.json` 的 `status` / `continuity.updated_at` / 与修正直接相关的 `continuity` 字段。
- **不做其他状态修改：** 不验证、不续写、不打标签、不增删知识点、不改 `knowledge_backlog`、`course_plan`、`parts`。
- **不需要 writing-core.md 或 style-benchmarks.md**——回答问题不是写教程，voice 照教程的 `voice` 字段语气作答即可；勘误也只做最小替换，不需要写作规则。
- 保持回答针对本教程的具体产物，使用其 voice。
